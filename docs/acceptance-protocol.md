# 本地初版验收与评测协议

日期：2026-11-01。当前目标为 GitHub 下载源码后本地体验的软件初版；多人在线、账号和远程部署不属于本轮。验收要求来源为 PRD AC-01～35 和本协议，执行事实只在验证报告记录。

## 1. 三类证据分开

| 层次 | 对象 | 合格记录 |
|---|---|---|
| 确定性与集成 | 应用事件→Workflow/工具/Router→结果和可靠保存 | 输入/确认版本、返回结果、持久化状态、副作用次数、失败恢复；模型/资料/存储适配器可打桩 |
| 非确定性判定 | 五类 judge、未来新模型能力另行加组 | 冻结代码/模型/prompt/量规，每条预先人工判断，记录输出、一致/不一致/错误及分层 |
| 用户持续学习 | 同一用户同一目标至少 5 次实际会话、至少 7 天 | 中断返回、至少间隔 16 小时的独立复验、起点/未见可比任务、帮助程度和失败；无提升百分比硬门槛 |

本地回归通过不等于模型评测通过，模型一致率不等于学习收益，候选数据存在也不等于完成独立验收。已有 35 条场景文件为规格化记录，execution=not_run，不是自动测试成功记录。

## 2. 本地初版核心验收

- 干净目录安装核心依赖，不要求启动 RAG 或下载 embedding 模型；缺 API 凭据给明确配置提示，不制造学习结果。
- 明确目标/容量/偏好，真实资料有来源，矩阵范围确认后测评；无法判断/未测分开，不强填期限与自评。
- 计划有来源、预算按讲解/练习/反馈总量，自审核通过并确认对应版本后才生效。
- 正式提交绑定原题/任务/量规；提问不计作答；判定失败保留提交，用户验收确认后一次推进。
- 独立/有辅助/未知与保持证据分开，不显示总体掌握百分比；综合任务覆盖必需标准，缺项补验。
- 暂停、退出、恢复、拒绝确认、版本冲突、取消及迟到结果均有明确状态；恢复不重建目标或重复应用。
- tools 只从本次允许的注册表调用；非法工具/参数拒绝；数据 Router 拒绝越域/敏感字段读取和伪造确认写入。
- L1/L2 来源与接续信息不丢失，删除/纠正使派生与缓存失效；关键提交可靠保存，辅助 IO 不按 token 执行。
- 首次本地体验给出清晰可读计划/反馈、等待进度、取消和配置/数据位置说明。CLI 是当前可运行入口；丰富桌面界面不作本轮先决条件。

每条缺陷以失败复现→修复→相关回归闭环，不删除与新规则冲突的测试来伪造达标。AC 覆盖表原有冲突/缺口均继续保留，未因新增数据关闭。

## 3. 数据分层与标签

原 dev 30 条继续用于开发；原 holdout 8 条保持不改，不宣称满足至少 30 条要求。本轮新建 acceptance-candidate 30 条，五类各 6 条、每类正常/边界/对抗各 2 条，每类有关键错误样例；全部为 synthetic_candidate、pending，未经人工复核或冻结。
人工需先按任务标准独立作答/标注，再与候选标签核对并记录 reviewer、处置和争议；未解决争议不能简单改成 reviewed。若用这些样本失败结果来改 prompt/规则，它们转为开发材料，正式独立验收另补未用于调优的数据。不能由模型把自己生成的标签标成已人工复核。
冻结前检查不同输入、身份、risk/judge 覆盖和关键名单，近似复写不能代替覆盖。编程为首轮范围；不以单领域结果声称任意领域普适。候选题量达到 30 只是数量就绪，不能保证统计充分或数据真正独立。

## 4. 执行与报告

`python evals/acceptance_protocol.py` 默认只校验格式、分布与就绪阻塞，绝不调用 API。schema 合格的候选清单可返回成功退出码，但输出 executed=false 和 human review pending，不是验收 PASS。
正式评测需 reviewed 标签及 reviewer、至少 30 条/五类各 6 条、正常/边界/对抗、关键名单；冻结清单保存 status=frozen 及默认检查输出的 configuration 原值，包含代码、prompt manifest、数据散列和模型/温度配置。真实运行显式提供 --live、--allow-holdout、--freeze-manifest 和 --out，且自行配置模型凭据。
runner 按整套数据运行三次，每次分别报告总体、judge/domain/risk、匹配/比对/错误、关键错误。每次一致率至少 90%、关键样例全过、有效覆盖完整；错误不从发布决定中隐藏，未覆盖不能通过。不能用三次平均/投票、只跑失败题或择优轮次替代。
代码与 prompt 正文变更必须更新版本/manifest，重新冻结并完整运行；已生成报告不追认到新配置。原 run_eval 的 --repeat 是探索报告，不等于正式三轮协议；探索误判或错误现在返回非零退出码。
本轮未执行真实 API；正式运行可能至少产生 90 次 judge 操作，加网络恢复另计。性能和费用只记录基线，不承诺当前读写策略已降低多少成本。

## 5. 未来能力与人工场景

矩阵覆盖、来源支持、计划审核、Decision/tool 选择、摘要忠实、7 天回顾尚未形成已上线模型契约；先按 workflow-scenarios 和应用返回做流程验收，再随契约加入独立模型能力组，不把旧五 judge 评测冒充覆盖这些新能力。
真实资料核验至少检查链接可访问、内容支持所引用条目、无法访问时如实说明；最终资料选择不得靠字符串相等验收。计划合理性按画像/前置/容量/标准逐项人工核对，评审结果记录而非默认为通过。
