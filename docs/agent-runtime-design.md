# 学习教练 Agent 运行设计

> 当前交付范围：GitHub 下载源码后本地运行的初版软件，不涉及多人线上运行。后端具体契约与工程默认值见 [本地后端设计](backend-design.md)；长期在线表述只作后续演进。


日期：2026-11-01。状态：目标设计、尚未实现。业务约束见 [Workflow 设计](workflow-design.md)，模块与所有权见 [产品系统设计](system-design.md)。当前代码仍为 MatrixSelector 驱动，不将本设计称为已经运行的 ReAct。

## 1. Agent 的定义与自主范围

主学习教练 Agent 在用户确认的目标和系统约束内，根据上下文与工具观察选择下一行动，反复执行直至完成、等待用户、受阻、取消或达到限制。学习规划/判定/检索等是它调用的能力，不因包含模型调用而分别成为 Agent。
主运行可采用 ReAct 式反馈决策，Workflow 提供硬约束。1.0 首先只在资料检索、计划生成和自审核修订开放动态选择；其他业务路径保留确定性选择。后续依据对照验证扩展追问/补强，不能把设计了统一循环等同于全流程均已开放自主权。

## 2. 运行内部组成

| 模块 | 输入与职责 | 输出 |
|---|---|---|
| 事件理解 | 用户输入/确认或工具事件，结合当前目标和状态 | 意图、结构化候选、待澄清项；不是最终业务授权 |
| 上下文请求 | 请求当前子目标需要的业务状态、证据、记忆、资料与检查点 | 带来源、读取版本、缺失项的 ContextBundle |
| 模型决策器 | 子目标、合法能力、历史行动与观察 | 类型化 Decision：行动、询问、等待、完成或受阻，附简短理由 |
| 受控执行接口 | 工具名、参数、相关身份/版本 | 执行器校验后调用；不接受任意 Python、任意状态写入或未知工具 |
| 观察处理 | 工具结果、有效性、业务实际生效状态和错误 | 供下一步决策的 Observation，不把故障转成学习不足 |
| 运行控制 | 步数/时间、取消、停止、去重、检查点及恢复 | RunResult 和可恢复状态 |

上下文组装是外部读取服务；运行内部只提出请求、消费结果。产品数据管理与访问层提供受控数据，用户与会话数据只是其中一类；所有上下文子查询和主动数据存取都经过 [领域 Router](data-access-design.md)，业务证据/授权不由摘要替代。

## 3. 单次循环协议

1. 应用服务创建 run_id，绑定可信主体、Way、子目标、业务快照及取消身份。
2. Workflow 给出合法行动，独立上下文服务按 [存取调度规则](data-access-design.md#7-存取调度与运行成本) 复用有效快照并增量组织完整输入；缺必要依据则询问或受阻，不伪装完成。
3. 决策器给出一个 Decision；首版每步只执行一个动作，便于追踪和控制副作用，不开启模型自行并发写入。
4. 执行器重新校验主体、作用域、输入契约、前置条件、权限、版本和执行限制；不通过返回明确观察，不运行工具。
5. 工具执行并返回结构化结果；有写入时由所属业务服务确认版本及实际保存状态。
6. 保存观察与检查点，更新剩余预算；仍需处理回到步骤 2，需要用户则输出并暂停，完成则返回成果引用。

ReAct 不要求记录完整内部推理；保留简短选择理由、动作/参数引用、观察与退出原因。模型说“已完成”仅是候选退出，系统按子目标产物和业务要求校验，失败不能以漂亮回复替代。

## 4. 契约

| 契约 | 必需内容 |
|---|---|
| RunRequest | principal、way_id、request_id、子目标/用途、输入引用、允许能力、预算策略、业务版本 |
| Decision | action/ask/wait/finish/blocked 之一；对应工具参数或问题/产物引用；简短理由 |
| ToolResult | invocation_id、成功/失败/无效/冲突/未知、对象与版本、来源、是否已保存、错误类别及可重试性 |
| Observation | 本步 ToolResult 引用、已确认事实、未满足条件、下一步可用信息 |
| RunCheckpoint | run/step、有效状态、已完成动作身份、依赖版本、待确认对象、取消/删除代际及恢复点 |
| RunResult | completed/waiting_user/blocked/cancelled/limit_reached/failed；产物引用、缺口、最后保存点 |

模型不能提供有效 principal、授权凭据、来源可信标记或自行提高预算。运行控制器填入可信字段，模型输出仅选择工具及内容参数。

## 5. 工具与数据服务

数据工具不直接访问存储。读取按领域 Router 校验主体/Way、用途和字段，写入按 Router 与领域命令检查来源、权限、版本与确认；身份凭据、完整管理策略和独立验收标签不对模型开放。运行控制器写检查点、执行层发评估事件的权限不自动授予 Agent。

能力分只读、生成候选、受控业务命令。检索/资料读取为只读工具；计划生成/审核/判定产生候选结果；激活计划、应用验收、纠正和删除由受控命令执行。
计划自审核仍是独立步骤和契约，不能靠生成提示词附一句“请自查”代替；后续 Review Agent 可承接该能力，而无需重定义用户确认和业务生效规则。
工具结果不足时允许补检索/修订，但不存在可自由更改画像或跳阶段的通用 set_state 工具。资料中包含的指令和旧对话中的确认不授予当前操作权限。

### 5.1 工具注册表与分发执行器

项目负责人确认工具调用采用简单的“工具注册表 + 分发执行器”。按当前任务选择可见 tools，模型返回工具名称及参数，程序查表、校验并调用对应处理函数，再将结构化结果交回模型。不增加模型工具路由器或任务树调度引擎。

注册表集中维护以下内容：

| 字段 | 用途 |
|---|---|
| name | 唯一且稳定的工具名，用于查表；重复注册在启动时拒绝 |
| description | 给模型的用途、输入要求及结果边界说明 |
| input_schema | 工具参数结构；执行前校验，不接受未定义参数 |
| handler | 程序内部绑定的处理函数，不向模型暴露可执行代码或函数路径 |
| task_groups | 当前哪些任务可见；同一工具可属于多个任务组，不重复实现 |

模型只接收可见工具的 name、description 和 input_schema。主体、Way、授权、请求身份由可信执行上下文传入，不作为模型可自填的授权参数。handler 继续使用前文定义的副作用、确认、版本、取消和调用限制规则，不另建一套。
分发流程为：工具请求 → 检查名称已注册且本次任务可用 → 参数校验 → 执行前业务/权限复核 → handler → ToolResult。调用时重新检查可用集合，不能只依靠提示词中隐藏工具。未知名称、不可用工具或非法参数直接返回明确错误，不进行动态导入、函数求值或任意代码执行。
工具注册表负责按名找到处理函数，领域 Router 负责处理函数内部的数据存取判断，两者职责分开。工具成功返回仍要区分内容是否有效、数据是否保存、业务是否生效。
现有能力 REGISTRY 是 Workflow 内部能力声明，不能直接全量暴露成模型 tools；仅将需要 Agent 自主选择的能力通过明确 handler 接入工具表，其余继续由确定性流程调用。任务分组先用配置映射实现，不提前引入树形引擎、独立节点预算或额外 Planner。
开发验证覆盖：重复工具名、未知/当前不可用工具、参数错误时 handler 不运行；同一工具跨任务复用；可信身份不可被参数覆盖；数据工具经过领域 Router；错误与实际保存状态如实返回。以上为设计要求，尚未实现或执行。

## 6. 停止、等待与恢复

完成必须有合格产物；等待用户必须有明确问题或确认对象；受阻要说明缺什么；取消/达到限制保留已保存结果和恢复点。询问输出后停止执行，不在内部猜用户回答。
动作步数、全运行时间与连续无进展阈值由配置策略显式提供，必须有限；工程起点已在本地后端设计确定为 12 动作/600 秒/连续 2 次同输入无进展，支持配置并须实测；不把单调用的 5 次/120 秒当作运行预算。非法配置不启用自主循环，返回配置缺项；当前确定性工作流仍可作为基线。
恢复前重新取得主体权限、Workflow 状态和依赖版本，不能直接继续使用旧快照。已记录成功的动作不重放；结果未知的副作用先核查，不能自动盲重试。旧请求已取消/超时/被替代或删除代际变化时，其结果不再应用。
在线目标下，用户连接和服务器 run 生命周期分开：页面断开不自动推断明确取消；作业状态可查询，显式取消由服务端处理。当前本地进程退出不能承诺继续后台执行。

## 7. 对照验证与开发顺序

先复用已有选择器注入点建立确定性基线，将执行与状态规则从选择器抽离，再接模型选择器；两条路径共用工具、输入校验、业务服务与授权规则。
同一子目标、初始状态、模型/工具配置及用户脚本下，比较合格产物、漏步骤/越权、恢复、重复无进展、用户负担、耗时与用量；不能只看最终回答。优先覆盖来源不足、审核失败、拒绝确认、取消、过期结果与调用失败。
记忆、工具、模型、存储适配器可替换，但本设计不要求重写框架或预建多个 Agent。先修已知判定/授权/恢复缺陷，再扩展模型可选择的范围。
