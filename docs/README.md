# 文档导航与维护约定

更新：2026-11-01。当前产品方向：围绕能力目标持续学习。运行代码版本仍为 v0.18，本次文档重整不代表功能版本升级。

PRD 1.0 已完成 O-01～O-09 决策并定稿，范围为本机单用户、单路径持续学习 MVP，十步闭环保留最小能力；本期主 Agent 自审核，独立 Review Agent 后续加入。需求定稿不代表代码交付或验收通过；当前缺口和未执行协议分别查交付清单与验证报告。

长期方向已明确为多人在线；当前本机 MVP 范围不变。目标设计现拆为系统、Workflow 和 Agent 运行三份；旧综合记忆规格的范围由 ADR-008 部分替代。

## 三种状态分开记录

- 需求证据：待验证 / 有初步证据 / 已验证（必须说明样本与适用边界）。
- 实现状态：未实现 / 部分实现 / 已实现 / 暂缓。
- 验证结果：未执行 / 通过 / 失败 / 跳过（注明日期、版本、方法）。
- 策略未定时使用“🔶 假设 / 🔵 待决策 / 策略草案”，不伪装成批准或验证结论；具体规范见术语表。

存在代码、存在单测、真实模型有效、用户真正受益是不同层次的证据。

## 更新落点

1. 产品要求改变：改 PRD；实现差距登记到交付清单。
2. 代码行为改变：改当前架构或记忆设计；更新交付清单；将实际验证结果写进验证报告。
3. 架构取舍改变：在架构决策中记录替代关系；旧决定不继续约束新实现。
4. 质量目标、指标定义与试用门槛在 PRD 定义；实际测试数量、跑分、延迟与证据在验证报告或运行报告记录，不能用实测值反向降低要求。
5. 版本经历与过期设计：进入历史记录或归档，不混入当前行为说明。
6. AC、测试断言或评测样本变化：同步验收覆盖映射；覆盖状态只描述证据范围，执行通过与否仍写验证报告。

PRD 描述应该怎样，架构描述现在怎样。二者不一致时必须登记差距，不能靠修改“已完成”文字消除。
