更新：2026-11-01。本文记录取舍；代码现状见 [当前架构](architecture.md)，待办状态见 [交付清单](delivery.md)。
历史原文见 [归档](history.md)。决策存在不表示其全部约束已被实现。

## ADR-001：围绕能力目标持续学习

- 决策：项目负责人在本次讨论中明确定位到持续学习，替代此前即时学习定位。
- 理由：产品需要支撑同一目标下跨次积累、接续、调整、复验与阶段回顾。
- 影响：任务继续作为执行单元，双层计划和记忆服务于长期能力目标；验收不能只看任务完成。
- 边界：不自动扩展到提醒服务、多用户或完整课程平台。连续使用收益仍待验证。
- 差距：目标字段、复验、暂停/调整、阶段回顾与收尾由交付清单跟踪。

## ADR-002：保持代码编排的单教练 Workflow（部分被 ADR-006 替代）

2026-10-14：下述矩阵选择范围为原决策；局部动态选择由 ADR-006 替代，单教练与系统守卫继续保留。

- 决策：保留自研状态机和矩阵执行；暂不切换框架或引入多 Agent。
- 理由：单用户、固定学习闭环需要可追溯的状态变化和模型输入。
- 取舍：自主性较低，但可以明确守卫、调用次序与错误处理；当前执行器仍需职责收敛。
- 重提条件：真实流程出现矩阵难以表达且无法局部解决的分支需求，再做对照验证。
- 替代方案：图框架、动态步骤提议、多 Agent 留待有证据时评估；不是既定开发任务。

## ADR-003：保留双层计划

- 决策：路线图表达能力目标与里程碑，执行窗口承载近期任务。
- 理由：持续学习需要方向稳定，同时允许近期安排随表现调整。
- 取舍：增加游标和窗口关联成本；应以接续与适应性验证价值。
- 边界：现有比例重估只反映重试负担，不称为完整学习速度模型。

## ADR-004：保留证据与叙事分工

- 决策：结构化证据支撑画像；摘要帮助对话连续性，不产生掌握结论。
- 理由：摘要具有损失和误写风险，不能替代判定来源。
- 取舍：存储采用有界保留，早期证据降采样为锚点，原文也会裁剪。
- 边界：可追溯程度受稳定身份和保留策略限制，不承诺“事实永不遗忘”。

## ADR-005：暂留单文件状态与可选 RAG

- 决策：保持单用户 JSON 状态，不先引入数据库；RAG 独立、默认关闭。
- 理由：当前主要风险是判定、数据关联和恢复语义，不是存储吞吐。
- 重提条件：出现多用户、并发写、不可接受的文件规模或明确内容来源需求。
- 代价：需统一原子写与恢复；可选依赖安装和打包也需清晰隔离。

## ADR-007：Way 作用域下的四模块记忆管理

## ADR-008：Workflow、Agent 与产品数据边界

## ADR-009：产品数据管理与领域 Router

## ADR-010：Electron 桌面与独立 Python 核心

2026-11-01：项目负责人选择 Electron。工程方案保留现有 Python 后端，以 TypeScript/React 开发界面；不将选择桌面框架扩大为整体 TypeScript 重写。主进程管理单个 Python 子进程，经版本化 stdio 协议调用统一应用接口；不新增本地 HTTP 服务。Python 独占业务数据写入，界面不复制确认/证据规则。

取舍：复用已有实现，但需要两套工具链、跨语言契约及子进程恢复验证。首期 GitHub 源码体验需准备 Node 与 Python，不承诺免环境安装包。PySide6 不作为本期界面依赖。详细技术选择、模块依赖和验证入口见 [技术选型与模块接口设计](technology-and-module-design.md)；设计不表示实现完成。

## 必须保留的约束

沿用原 I 编号，供代码注释与测试追溯。以下是约束，不是全部通过验证的声明。

| 编号 | 约束 |
|---|---|
| I-1 | 阶段转换由 stages.py 的守卫决定，模型不能直接决定推进 |
| I-2 | 现有实现的对话阶段使用本轮起始阶段；改变时序须验证防抢答与题目关联 |
| I-3 | 当前权威状态优先于历史自述，放在历史之后注入 |
| I-4 | 不可逆动作需明确确认；未登记动作拒绝 |
| I-5 | 能力声明副作用级别；未知级别按危险动作处理 |
| I-6 | 步骤选择不得越过当前阶段的合法动作集；动态提议尚未实现 |
| I-7 | 目标或方案实质变化需说明并确认 |
| I-8 | 状态键有归属，能力写入应与声明一致 |
| I-9 | 趣味化或鼓励不得改变判定和画像 |
| I-10 | 证据要求及放行规则由代码契约约束，模型不能自行放宽；当前语义质量仍需人工复核 |
| I-11 | 自评仅作起点参考，不作为已掌握证据 |
| I-12 | 判定证据带来源、时间/序号，并能关联到实际任务 |
| I-13 | 保留期内原文有回取路径；超期裁剪应留痕 |
| I-14 | 摘要不能成为掌握度或薄弱点的判定来源 |

I-2 原先用于修复教练抢答，不能据此保留已经发现的测评关联错误；两项要求需同时满足。
I-4、I-7、I-10、I-12 等仍有实现差距，见交付清单。约束不能通过文字标记视为完成。
