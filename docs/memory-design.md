## 0. 术语（先钉死，避免歧义）

| 词 | 含义 | 代码位置 |
|---|---|---|
| **计划块** | 一批可执行计划（3–5 个单次学习）；"滚动"指的就是它 | `current_window` |
| **单次学习** | 用户**一次坐下来学**的时间块（"每天学 1h" → 那 1h） | `current_window.days[i]`、游标 `plan_progress.day`、时长上限 `session_minutes` |
| **任务** | 单次学习内为达成目标的一个最小可执行单元 | `days[i].tasks[j]`、`today_task` |

"窗口"在本项目有**两个互不相干**的含义，本文**只用「计划块」指第一个**：

| 叫法 | 是什么 | 谁决定 | 当前值 |
|---|---|---|---|
| **上下文窗口** | 模型一次能接收的 token 上限 | **模型**（是能力，不是我们的策略） | DeepSeek 官方页：**1M** |
| **注入窗口** | 我们每轮往 `messages` 里塞多少历史 | **我们的代码** | 固定 **8 条消息**（= 4 轮对话） |

## 1. 问题：遗忘

"遗忘"不是一个问题，是**五个**：

| # | 形态 | 现状 | 后果 |
|---|---|---|---|
| **忘-1** | 单次学习内**该记住的没记住** | 注入 8 条 ≈ 12 分钟 | 一次 120 分钟的学习，前面 90% 对模型不存在 |
| **忘-2** | **跨单次学习没有叙事记忆** | 只有结构化状态 + 上次末尾的 8 条消息 | 用户三天后回来，系统不知道"上次聊了什么、你卡在哪、为什么" |
| **忘-3** | **记住了但找不回来** | `conversation_archive` 全仓**无任何读取路径** | 数据在文件里，但等于没有 |
| **忘-4** | **该忘的没忘**（污染） | `skill_profile` / `weak_points` **无时间戳** | 三个月前的判定 = 今天的判定 |
| **忘-5** | **失败被覆盖** | `latest_result` 是单槽，重做成功即覆盖 | "我在这个知识点上犯过什么错"永久丢失 |

### 1.1 现状量化（按每 3 分钟一轮对话估算）

| 现有常量 | 容量 | 换算 |
|---|---|---|
| `CONVERSATION_WINDOW = 8` | 8 条 = **4 轮** | 模型只看得到最近约 **12 分钟** |
| `CONVERSATION_ARCHIVE_LIMIT = 500` | 500 条 = 250 轮 | 约 **12.5 小时**学习量，之后 `del archive[:-500]` **静默丢弃** |
| 20h/周 的用户 | 10 次单次学习/周 × 约 80 条 | **约 800 条/周** → **不到 4 天**触顶 |

> **"1M 上下文"不等于不会出问题**：单次学习时长无上限（用户可自报任意值）、模型会换、而且 `conversation_history` **根本不按单次学习切分**（它是一条跨周累积的连续日志）。
> **正确的目标是：注入量 O(1)，与对话轮数无关。** 这样"上限"问题自动消失，成本与注意力质量一起解决。

## 2. 与 v0.16 决策的关系（为什么现在反过来做）

v0.16 明确拒绝了"阶段小结"，理由是：

> 要多一次模型调用，直接撞"每轮调用数受控"护栏；窗口化本身已解决 90% 的成本问题。（architecture.md §12.3）

**现在的判断：v0.16 解决的是成本，没有解决遗忘。**

- 窗口化把"每轮注入多少"控住了 ✓
- 但窗口外的内容**永久不可见** —— 而这一点被当成"已解决"了 ✗

**所以本设计的目标不是省钱，是"不遗忘"。** 这也解释了为什么压缩值得花模型调用：它买的不是 token，是**连续性**。

---

## 3. 核心原则：**压缩的是叙事，不是事实**

压缩必然有损，而"遗忘"和"压缩"本来是对立的。唯一的出路是**分工**：

| 层 | 性质 | 会因压缩而丢吗 | 回答的问题 |
|---|---|---|---|
| **事实层** | 结构化、无损、**永不压缩** | ❌ 不会 | 系统**知道**什么 |
| **叙事层** | 文本、有损、压缩 | ✅ 会（可接受） | 怎么把它**讲成人话** |
| **原文层** | 留存、**不注入** | ❌ 不会 | 仅审计与核对 |

> **一句话：事实永不遗忘；遗忘只发生在"怎么讲故事"上。**

## 4. 两层结构

```
┌─ 长期记忆 ────────────────────────────────────────────────┐
│  事实层（无损 · 结构化 · 永不压缩）                          │
│    evidence[]        知识点 → [(at, session_seq, 来源,        │
│                                  判定, 错误类型, 任务id)]     │
│    session_records[] 单次学习 → {序号, 完成任务, 涉及知识点,   │
│                                  卡点, 下一步, 尝试次数}       │
│  派生视图（不直接写，由事实算出）                             │
│    skill_profile / weak_points / due_for_review              │
├─ 短期记忆 ────────────────────────────────────────────────┤
│  叙事层（有损 · 压缩）                                       │
│    rolling_summary     本次单次学习内滚动（单槽，替换不追加）   │
│    session_summaries   每次单次学习定稿一条（有上界 M）        │
│  注入窗口（原文）                                            │
│    最近若干条（按**字符预算**动态取）                          │
├─ 原文层 ──────────────────────────────────────────────────┤
│  conversation_archive  按单次学习分段留存，仅审计 / 可回取     │
└──────────────────────────────────────────────────────────┘
```

## 5. 长期记忆

### 5.1 事实层（唯一可写的东西）

```python
evidence: {
  "<知识点>": [
    {"at": "...", "session_seq": 7, "source": "evaluation" | "assessment",
     "verdict": "pass" | "retry", "score": 0.5,
     "error_type": "概念混淆", "task_id": "3-2"},
    ...
  ]
}
session_records: [
  {"seq": 7, "day": 3, "at": "...", "tasks_done": ["3-1", "3-2"],
   "topics": ["groupby 聚合"], "stuck": ["多列 agg 语法"],
   "next": "重做 3-2", "attempts": 3},
  ...
]
```

**要点**：
- `error_type` 落进 evidence → 修 **忘-5**（现在被单槽覆盖）
- 每条 evidence 带 `session_seq` → 修 **忘-4** 与复习调度（§7）
- `session_records` → 修 **忘-2**

### 5.2 派生视图（**不直接写**）

| 派生 | 来自 | 替换掉 |
|---|---|---|
| `skill_profile` | `derive_profile(evidence)` | 现在有**两条**写入路径且语义不一致：测评 `= scores`（整体覆盖，`assessment_rules.py:116`）vs 验收 `(old+new)/2`（平滑，`evaluation.py:79`）。**合并规则收敛到唯一函数** |
| `weak_points` | `derive_weak_points(skill_profile)` | 不变（阈值 <0.6） |
| `due_for_review` | `derive_due_for_review(evidence, session_seq)` | 新增（§7） |

### 5.3 写入者表（**I-8 的载体**）

| 长期记忆字段 | 唯一写入者 |
|---|---|
| 目标 / 水平 / 单次时长 / 期限 | `perception.profile_extract`（空值不覆盖；**改目标 = danger**） |
| 偏好 `preferences` | `perception.profile_extract` + 行为推断 |
| **evidence** | `evaluation.judge`（验收）/ `memory.assessment_finalize`（测评） |
| **session_records** | `memory.condense_cycle`（§6.2 L2） |
| 能力画像 / 薄弱点 / 待复验 | **无直接写入者** —— 一律由 evidence 派生 |

### 5.4 序号与时间

- `state["session_seq"]`：**单调递增**的单次学习序号（`plan_progress.day` 每个计划块会重置，**不能**当序号用）
- 每条 evidence / session_record / session_summary 都带 `at` 与 `session_seq`
- 没有这两个字段，"遗忘"与"记住"都**无从定义**

## 6. 短期记忆

### 6.1 注入结构（每轮，与对话轮数无关）

```
① 当前权威状态（`render_profile`，有预算）        ← 变化慢，靠前利于上下文缓存
② 本次单次学习的进行中摘要（1 条）                  ← L1 产物
③ 最近若干条原文（按**字符预算**动态取，不是固定 8 条）
④ 最近 M 条单次学习摘要                             ← L2 产物
⑤ 本轮用户输入
```

**把"固定条数"改成"固定预算"**：条数无法适配不同长度的对话，预算可以。

### 6.2 两级压缩

| 级别 | 触发 | 产物 | 调模型 |
|---|---|---|---|
| **L1 单次学习内** | **注入字符数 > 预算** | `rolling_summary`：**替换**（不是追加） | 是（+1） |
| **L2 单次学习结束** | `cursor.is_day_complete(state, day)` 为真（**该函数已存在**） | 一条 `session_summary`，追加进 `session_summaries` | 是（+1） |

**L1 的三条设计约束**：
1. 入参是 `(现有 rolling_summary + 被挤出的原文)` → 出新 `rolling_summary`
2. **替换而非追加** —— 否则摘要自己也线性增长
3. 最近 `MIN_RAW_MESSAGES` 条原文**永不被压缩**

**L2 幂等**：靠**顶层** `state["condensed_through_seq"]`，防止同一单次学习被反复压缩。
（放顶层而不是 `plan_progress`：窗口滚动会整体重置游标，放里面会被清零并导致重复压缩。）

**L2 之后**：`rolling_summary` 清空；定稿摘要**只追加、永不参与 L1 压缩**（避免层层失真）。

### 6.3 摘要的三条硬约束

| # | 约束 |
|---|---|
| 1 | **只写过程事实**：本次单次学习做了哪几个任务、各自验收的**动作**（通过 / 重做）、卡在哪、涉及哪些知识点 |
| 2 | **不得写判定**：掌握度、薄弱点、任何"他会了/不会"的结论。判定**只能**来自 evidence（I-9 / I-10 / I-14） |
| 3 | **知识点名由代码提供**，模型**不得自创或改名** —— 否则摘要会给画像引入一个不存在的术语 |

→ 因此摘要 = **结构化骨架 + 模型润色**，不是自由发挥：

```
代码给的骨架（确定性）：
  单次学习 3｜任务：① DataFrame 筛选(通过) ② groupby 聚合(重做)
  知识点：DataFrame 筛选、groupby 聚合｜尝试次数：3

模型只负责把这行写成一句人话。
```

**验证**：必须有断言 —— **摘要文本不得出现在 `skill_profile` / `weak_points` / `latest_result` 里**。

### 6.4 失败兜底

压缩**必然**会遇到这些失败（`coach/llm/client.py` 现在把异常原样抛出）：

缺 API Key · 网络不通 / 超时 · 429 限流 · 401 鉴权 · **400（模型名下线 / 参数不被接受）** · 5xx · 余额不足 · 返回不是合法 JSON · 字段缺失（Pydantic 校验失败） · 内容被截断 · 返回空

> ⚠️ 附带隐患：`_create()` 现在**没有设 timeout 与 retry**，网络挂住会一直等 TCP 默认超时。

**兜底沿用项目既有纪律**（失败必须有确定性出口，绝不留空、绝不抛出）：

| 位置 | 现有做法 |
|---|---|
| `services/coach.py` 对话 | 返回 `FALLBACK_REPLY` |
| `services/evaluation.py` 判定 | 返回 `None` → **保持阶段，不写假判定** |
| `services/planning.py` 生成方案 | 确定性兜底方案 |
| **压缩（本文）** | **退化为确定性摘要**（骨架直接当摘要用） |

```
[单次学习 3] 完成 2 个任务：① DataFrame 筛选 —— 通过；② groupby 聚合 —— 重做。
涉及知识点：DataFrame 筛选、groupby 聚合。尝试 3 次。
```

## 7. 复习调度：**标记待复验**

**不是阶段，是一条排序规则**（v0.16 删掉的是"一个没有任何转换指向的空阶段"，那个判断仍然成立；这里补的是它当时缺的**序号维度**）。

```
① 每条 evidence 带 session_seq
② 派生：uncovered = state["session_seq"] - max(evidence[知识点].session_seq)
         ≥ 8  →  进入 due_for_review
③ 消费点：生成**下一个计划块**时（planning.generate_plan / roll_window）
         把 due_for_review 作为入参交给模型，要求优先安排
```

**"覆盖"的定义**：本次单次学习里有任务**涉及**该知识点（无论验收是否通过）。
若没通过，它已经在 `weak_points` 里被优先安排，**不需要再叠一个待复验**。

**为什么不用自然日**：本项目以"**次**"为基本单位；"连续 8 次单次学习没碰过"比"14 天"更贴近真实的遗忘。

**什么时候才需要"阶段"**：当"到期复习"要成为**一次只做复习的独立单次学习**时。现在不做。

## 8. 存储与保留

### 8.1 继续用单文件 JSON

| 项 | 值 |
|---|---|
| 文件 | `data/user_state.json`（`coach/storage/state_store.py:22`） |
| 现状 | 24.5 KB；一年重度使用增量约 **200–300 KB** |
| 对照 | `data/rag/models/bge-m3/onnx/model.onnx_data` = **2.27 GB** |

**结论：state 文件不会无限膨胀**，因为注入窗口、归档、画像各自都有界。真正无界的是 `data/metrics/events.jsonl` —— 全仓唯一的删除逻辑只有备份裁剪（`KEEP_BACKUPS = 5`），metrics **无任何轮转**。

### 8.2 要做的不是"换存储"，是"给无界项加上界 + 留痕"

| 项 | 上界策略 |
|---|---|
| `evidence` | 每个知识点保留最近 **K=5** 条明细；更早的**降采样**成统计值（次数 / 均值 / 最近时间） |
| `session_summaries` | 保留最近 **M=20** 条；更早的做**确定性汇总**成一条"里程碑级摘要"（**不再调模型**，避免二级失真） |
| `conversation_archive` | **改结构**：`[{session_seq, messages}, ...]`，保留最近 **K=30 次单次学习**；丢弃时**必须留痕**（metric event） |
| `data/metrics/events.jsonl` | 按月轮转 |

### 8.3 逃生舱与触发条件

**逃生舱（低成本前置投资）**：建 `domain/zones.py` 的**区视图** —— `ZONE_OF`（每个 state 键属于哪一区）+ 每区保留策略表 + 契约测试。这样将来真要拆文件时**只改落盘层**，业务代码不感知。

**什么时候才真的拆**（可测的触发条件，而非凭感觉）：

- `user_state.json` > **5 MB**，或
- 单次 `save_state` > **50 ms**，或
- 归档触上限频率 > **每周 1 次**

满足任一条 → 拆成 `profile.json` / `progress.json` / `runtime.json` / `history.jsonl`。
**仍不推荐 SQLite**：单用户单机用不上事务、并发、查询，而多文件会引入"跨文件一致性"这个**全新的缺陷类别**。

## 10. 不变量（拟新增）

| # | 不变量 | 违反后 |
|---|---|---|
| **I-12** | **记忆必有来源与时间**：写入长期记忆的判定必须带来源（哪次测评/验收）与序号 / 时间；**无来源的结论不得进入判定性字段** | 无法归因、无法遗忘；"这个分数怎么来的"永远答不出 |
| **I-13** | **归档不是黑洞**：移出注入窗口的信息必须存在**确定性回取路径**；任何静默丢弃（归档超限）**必须留痕** | "窗口化"退化成"截断"，用户说了等于没说 |
| **I-14** | **压缩不得承载判定**：摘要只写过程事实，不得写入掌握度 / 薄弱点 / 结论 | 模型生成的文本绕过 I-9 / I-10，成为新的记忆污染面 |

## 11. 落地顺序与验收

**原则：先做零模型调用的部分，再做压缩。** 前者纯确定性、可单测、风险最低。

| 序 | 内容 | 调模型 | 验收 |
|---|---|---|---|
| **M1** | state 加 `session_seq` / `evidence` / `session_records` + 幂等迁移 | 否 | 旧 state 文件不炸；`ensure_keys` 补齐 |
| **M2** | evidence 写入（`evaluation.judge` / `assessment_finalize` 追加）；`derive_profile` 取代两条就地写入路径 | 否 | **同一批验收记录，改造前后的 `skill_profile` 一致或可解释**；每条判定可追溯到来源与序号 |
| **M3** | `error_type` 落进 evidence | 否 | 重做后仍能查到上一次的错误类型（**忘-5**） |
| **M4** | `derive_due_for_review` + 生成计划块时作为入参 | 否 | "连续 8 次未覆盖"的知识点出现在下一个计划块里（**§7**） |
| **M5** | `clamp_session_minutes` → [15, 120] | 否 | ⚠️ **行为变化**：用户说 4 小时时被钳到 120 并**明确告知** |
| **M6** | 归档改分段结构 + K=30 + 丢弃留痕 | 否 | 归档触顶时产生 metric event；按次保留正确 |
| **M7** | 注入改按**字符预算** | 否 | 80 条消息的对话里，注入量 ≤ 预算且最近原文优先 |
| **M8** | **L2** 定稿摘要（先做：触发明确、频率低） | 是 | 摘要不含判定字段；失败退化为确定性摘要 |

## 12. 明确不做

| 不做 | 理由 |
|---|---|
| 五层记忆抽象（长期 / 计划 / 短期窗口 / **工具** / **提议**） | 其中两层是为不存在的功能预留的（工具缓存、提议历史）。⚠️ **阶段 B 上工具后，"工具记忆/缓存"会重新变成真问题** —— 届时单独评估 |
| 向量检索 / 独立记忆库 | 事实层是**结构化**的，按知识点 / 序号 / 错误类型确定性检索即可 |
| 拆分存储文件 / SQLite | 触发条件（§8.3）未满足；多文件会引入跨文件一致性缺陷 |
| "阶段小结"（每次阶段切换一条） | 改为按**单次学习**（§6.2 L2）—— 边界对用户有意义，阶段边界对用户不可见 |
| 把归档原文当作记忆来回取 | 原文层**仅审计**；记忆靠事实层与叙事层，不靠翻原文 |
