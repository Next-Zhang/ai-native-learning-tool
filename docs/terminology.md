# 术语与文档规范

更新日期：2026-10-14。适用于当前产品文档；历史快照、代码标识和原始评测数据保留原样。
本页统一语言，不改变业务代码或宣称新能力已经实现。产品规则见 [PRD](PRD.md)，代码现状见 [当前架构](architecture.md)。

2026-11-01 口径补充：产品主框架指输入/理解/决策/执行/反馈/输出六部分系统职责；Workflow 规定业务依赖和状态放行；Agent 指在约束内选择行动并基于观察继续的运行核心。上下文是跨数据来源的读取能力，狭义记忆不包揽业务证据、资料或运行检查点。

## 1. 核心术语

最新口径：产品数据管理与访问层是产品层数据服务的总称；领域 Router 对各类数据的 Agent 存取作准入判断；用户与会话数据服务负责偏好/交流/接续信息。“记忆 Router”仅指其中 UserSessionRouter 的候选准入职责，不能代指全产品数据访问。

| 推荐名称 | 定义 | 使用边界 |
|---|---|---|
| AI 学习教练 | 帮助学习者围绕能力目标持续练习、获得反馈与接续进度的产品角色 | 首次出现可称学习教练 Agent；不暗示模型拥有全部决策权 |
| 工作流（Workflow） | 由代码约束阶段和合法操作的执行方式 | 当前架构；与模型动态选择步骤的 Agent 执行方式区分 |
| 记忆 Router | 对带来源的候选做分类、准入和存储分发的模块 | 模型可提取候选，不能自行授予证据资格或确认；业务状态按原规则更新 |
| 上下文组装与注入 | 按当前任务从有效记录读取并组织模型输入的模块 | 先限定 Way/版本，必需原文缺失或超限要说明，不靠摘要冒充核验 |
| 记忆生命周期管理 | 按用途/有效性/依赖管理合并、失效、压缩和清理的模块 | 代码执行规则，模型辅助识别；处理派生与索引，旧记忆不默认永久保留 |
| 局部 ReAct | 围绕阶段内子目标，选择行动、执行、观察结果并重新决策的循环 | 系统限定合法能力及状态写入；完成、等待用户、受阻或达到限制时退出；不是整个产品自由循环 |
| Agent 执行计划 | 为完成某次请求安排的工具操作与子任务 | 与面向用户的学习计划区分；本期不引入完整 Plan-and-Execute 架构 |
| 持续学习 | 围绕同一能力目标跨多个学习会话积累、补强和复验 | 不等于持续聊天、后台运行或定时提醒 |
| 学习目标 | 用户希望形成的可应用能力，包含用途、范围和目标达成标准 | 不把 `learning_goal` 当前字符串当作完整目标模型 |
| 学习路径（Way） | 承载一个学习目标及其路线图、任务、进度、提交、证据和对话记忆的产品对象 | 当前只做单路径；后续可保留多个、每次只激活一个，切换不清空其他路径；不与路线图混用 |
| 目标达成标准 | 开始前确认的目标产出、必需标准、允许资料/工具与独立要求 | 综合任务逐项覆盖全部必需标准，缺项补验；与单任务验收标准区分；应用达成不等于长期掌握 |
| 能力矩阵 | 学习目标对应的能力点、必要前置及可观察标准 | 范围先确认，测评与证据按能力点关联，未测不视为零分 |
| 参考资料库 | 按学习目标整理的真实来源及其能力关联、用途和访问记录 | 1.0 以官方文档为主，不默认要求向量数据库或视频解析 |
| 计划自审核 | 主 Agent 对指定版本计划的来源、画像匹配及合理性作显式检查 | 不通过退回修订；不等同独立审核，未来 Review Agent 可承接该职责 |
| 用户确认验收 | 用户接受本次任务结果及学习收尾 | 未确认不按已验收推进，确认不替代有效判定或独立证据 |
| 计划回顾周期 | 每 7 天根据实际表现回顾并决定保持或调整安排 | 可在返回时处理，记录周期范围，不等同自用观察周期或计划单元 |
| 路线图 | 学习目标及其里程碑的整体安排 | 不用“计划”同时指路线图和任务列表 |
| 里程碑 | 路线图中具有阶段达成标准的能力子目标 | 排完任务不自动达成；标准及对应独立证据达标可推进，不必等待复验；保持单独展示 |
| 执行窗口 | 当前已生成的近期任务安排，包含若干计划单元 | `current_window`；旧称“计划块”仅用于历史说明 |
| 计划单元 | 执行窗口中的一组预计可在一次学习会话内完成的任务 | 是安排，不是实际发生的会话；代码 `days`/`day` 不一定指自然日 |
| 学习会话 | 用户实际开始学习到主动结束、暂停、退出或使交互无法继续的异常中断的一段交互 | 不按无交互自动结束；跨日、计划游标递增或单次 API 失败不自动切分；返回创建新会话并接续任务 |
| 对话轮 | 一次用户输入及系统相应处理和回复 | 多轮可属于同一学习会话 |
| 任务 | 具有练习要求、交付物和验收标准的最小执行对象 | 有稳定身份；修改要求需区分版本 |
| 提交 | 用户明确交付给某项任务或题目的作答 | 提问、请求提示不自动算提交 |
| 知识点 | 可重复练习与复验的技能或概念单元 | 名称可显示给用户，身份不能仅靠模型措辞 |
| 起点测评 | 建立初始表现证据的评估 | 可使用自评选题，自评不成为判定 |
| 任务验收 | 对实际任务及提交按预先约定标准进行判断 | 与产品功能验收区分 |
| 复验 | 在后续学习会话以相关但未原样复用的任务再测既有知识点 | 目的可为确认补强、迁移或保持；不使用含混的“复习调度”代替 |
| 自动复验 | 系统从合格候选中安排的复验任务，可覆盖多个相关知识点 | 每实际会话至多一个任务；按补强确认→首次保持→已有保持再验排序，同类按时间；告知各项原因及用时/预算，逐点留证；可跳过且不自动补发 |
| 学习证据 | 有来源并关联题目/任务、提交、结果和时间的有效表现记录 | 系统故障、摘要和自述不属于能力证据 |
| 用户画像 | 关于目标、起点、容量、偏好及表现的结构化认识 | 区分用户提供的信息与系统基于证据派生的判断 |
| 学习摘要 | 帮助接续的过程叙述 | 不替代能力证据，不授予操作权限 |
| 时间预算 | 用户明确给出的单次可投入时长，涵盖讲解、练习和反馈 | 不设统一最低时长；动态分配、不固定比例；总量受其约束，不自动增加 |
| 人工确认（HITL） | 用户对明确操作及影响作出的授权 | 登记过动作不等于已获得确认 |
| 逻辑模型调用 | 一次目的和输入不变的模型操作，包含首次请求及其网络重试 | 不等于对话轮；含首次最多 5 次请求、请求及间隔总等待最多 120 秒，先到即停；跨层统一计数 |
| 自动重试 | 对临时请求故障再次发起同一逻辑调用的请求 | 首次不算重试；本版最多 4 次自动重试，配置错误/无效输出不进入该循环 |
| 迟到结果 | 在请求取消、超时终止或被重试取代后才返回的结果 | 不应用至进度、证据或对话记忆，不覆盖新结果；已成功保存的有效结果不因此回滚 |

## 2. 判定与帮助程度

| 推荐名称 | 含义 | 不可推出的结论 |
|---|---|---|
| 任务完成 | 当前交付物满足本任务验收标准 | 不能直接推出独立性或长期掌握 |
| 任务部分完成 | 有可用产出，但部分必需标准未满足 | 不能当作完全通过 |
| 任务未完成 | 有效判定表明必需标准未满足 | 不包含 API 故障、缺少题目或无效模型输出 |
| 无法判断 | 证据不足、判定无效或能力边界限制导致没有有效结论 | 不能写成零分或能力不足 |
| 有辅助完成 | 发生影响作答的指导，完成结果仍可用于学习反馈 | 不能计为独立应用证据 |
| 独立完成（已声明/已记录） | 在当前可观察记录中未使用答案或影响作答的提示，用户也未声明外部辅助 | 不保证系统看不到的外部辅助不存在；展示来源与边界 |
| 已有独立应用证据 | 一条合格表现即可展示：明确知识点及约定难度、未做过的同类任务、有效通过标准且无影响作答的提示/答案；允许约定资料；帮助有记录/声明 | 展示任务、时间、数量及帮助来源；未知不计独立；不等于掌握、跨次保持或任意情境通用 |
| 待复验 | 需要后续会话补充表现证据 | 不等于遗忘或未掌握 |
| 已有跨次保持证据 | 关联原独立应用证据，后续实际会话以另一新任务独立复验一次，原有效提交到复验首次呈现至少间隔 16 小时 | 展示实际间隔与关联任务；时间未知/不足不推定达标；16 小时为产品阈值，不证明长期、永久或全面掌握 |
| 能力掌握 | 综合目标标准、独立应用与跨次证据的有限结论 | 不能仅由完成度映射得出；展示证据范围和时间 |

用户不愿说明帮助程度时记“未知”；未知不按独立处理。查看参考资料本身是否影响独立性，由任务事先规定，例如可查 API 文档的开放资料任务。
产品展示规范已确定：任务结果、帮助程度、独立应用证据、跨次保持证据分别呈现，不用总体掌握分数或百分比概括能力。“待复验”是独立标记，不表示能力下降；无有效证据不映射为零分。

## 3. 文档状态与规范用语

- “必须”：功能验收硬要求；“应”：默认产品行为，例外要说明；“可以”：可选行为。
- 🔶 假设：合理但未得到用户或数据验证；不能写成事实。
- 🔵 待决策：尚无批准值或方案；注明所阻塞的交付。
- “策略草案”：为讨论提供的具体候选，不当成用户已经逐项批准或已验证的策略。

| 维度 | 允许值 | 维护位置 |
|---|---|---|
| 需求证据 | 待验证 / 有初步证据 / 已验证 | PRD 引用验证记录 |
| 实现状态 | 未实现 / 部分实现 / 已实现 / 暂缓 | 交付清单 |
| 验证结果 | 未执行 / 通过 / 失败 / 跳过 | 验证报告或运行报告 |
| 交付范围 | 核心 / 后续 / 暂缓 | PRD；不与缺陷严重级混用 |
| 规格覆盖 | 直接覆盖 / 部分覆盖 / 缺口 / 冲突 | 验收覆盖映射；不等于运行通过/失败 |

代码符号用反引号；产品正文优先中文。统一使用“任务验收”“复验”“执行窗口”“学习会话”，不交替写判卷/复习/计划块/单次学习表达同一对象。
数字与单位保留空格，例如“30 分钟”；日期统一 YYYY-MM-DD；章节采用连续编号与简短标题。
表格放并行规则、映射和案例，解释与取舍使用段落。实现状态与历史测试数不复制进每张需求表。

## 4. 标识规范

| 前缀 | 对象 |
|---|---|
| UR- | 用户需求，沿用原编号 |
| FL- | 用户流程 |
| BR- | 业务规则 |
| AI- | AI 能力契约 |
| AC- | 产品功能验收案例 |
| M- | 质量与效果指标，保留 M-01～M-05 |
| O- | 产品决策事项，含已确定事项；PRD 1.0 的 O-01～O-09 已确定，旧 O 编号到历史快照追溯 |
| D- / C- / R- | 缺陷 / 持续学习实现差距 / 结构整理候选 |
| T- | 验证报告中的测试场景分类，可关联多个 AC |
| ADR- / I- | 设计决策 / 约束，沿用原编号 |

新增编号只追加、不复用；删除对象保留撤销说明。旧 S/F/X 编号仅用于历史追溯。
AI- 能力是产品契约，不要求与代码 REGISTRY 一一同名；AC- 是验收规格，不宣称已有对应自动测试。
