# ADR-006：外层工作流约束与局部 ReAct

2026-10-14，项目负责人确认采用外层工作流约束与局部 ReAct。十步业务闭环已有明确依赖与确认点，资料检索、计划生成和自审核修订又需要依据执行结果选择后续操作，因此在这些局部环节引入行动反馈循环。本决策部分替代 ADR-002 的“全部步骤由矩阵选择”，保留单教练、代码守卫和用户确认边界；尚未实现。

外层系统提供子目标、当前状态及合法能力集合；模型提出动作与输入；共用执行器再次检查前置条件、参数、权限与状态版本，执行后返回明确结果供下一次选择。保存证据、阶段推进、周期是否到达等由系统规则控制，不能由模型自述直接改变。

1.0 首先覆盖资料检索与计划生成/自审核；学习中的追问和补强可在验证后扩展。固定工作流保留为对照基线，两条路径共用工具、契约、状态与授权检查。退出类型为完成、等待用户、受阻、达到限制；取消按已有恢复规则处理。等待用户时暂停并保存，不在循环中代替用户确认。

动作总数、总体耗时、重复无进展阈值尚待实现设计确定；有限执行是要求，具体数值未批准。每逻辑调用的 5 次请求/120 秒仅约束网络恢复，不是整个行动循环预算。记录动作、简短理由、结果、状态变化和退出原因，不要求完整内部推理日志。

考虑过继续全固定工作流、全局自由 ReAct 和 Plan-and-Execute。保留固定工作流能降低调试成本，但灵活分支需逐项编码；全局自由循环会增加维持业务依赖的成本；完整 Plan-and-Execute 暂无必要为既定主流程增加规划层。学习计划是面向用户的产物，与 Agent 执行步骤计划分别建模。

此选择增加循环恢复、行动轨迹评测与成本观测的工作。需用相同初始状态、工具、模型配置和用户脚本对照闭环质量、漏步骤/越权、无效动作、恢复、耗时与用量；没有实测不能宣称优于工作流。独立 Review Agent 后续可承接审核契约，本次不增加该角色或确定新的技术框架。
