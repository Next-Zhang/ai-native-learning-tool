# Prompt 库管理

日期：2026-11-01。当前交付为 GitHub 源码下载、本机单用户运行体验。已实现静态 prompt 清单与离线检查，未将未来能力伪装成现有 prompt。

## 当前库与版本

现有 14 个任务/上下文常量和 6 个阶段 prompt 共 20 项，统一登记稳定 ID、语义版本、内容 SHA-256、用途、输出契约、关联 AC 和 legacy_current 状态。正文继续由原模块唯一维护，服务原导入方式不变；manifest 是审核锁，不是第二份正文。
legacy_current 表示当前代码使用，不能解释为符合最新 PRD。确认判定只是模型意见；独立证据、来源真实性、授权与预算由系统校验，不能用提示词修补代码缺陷后宣称验收通过。
统一模型入口把命中的静态 prompt ID/版本/散列挂到单轮 trace；不复制动态用户数据到 prompt 元数据。trace 未开启时不因本功能落盘，不增加模型调用。

## 操作与修改规则

`python -m coach.prompts.catalog` 查看只含静态元数据的清单；`python -m coach.prompts.catalog --check` 校验内容与 manifest、漏注册和重复 ID。未知 ID 显式报错。包分发包含 manifest。
修改顺序：明确受影响契约/AC → 只看 dev 样本及失败记录 → 修改正文和对应版本 → 更新 manifest → 运行离线契约/相关业务测试 → 在新冻结配置下运行模型评测。不能仅更新散列来规避评审；语义变化更新版本并说明原因，运行报告引用 manifest 哈希。
原 0.18.0 为当前正文基线；兼容性说明调整可升 patch，行为/rubric 改变升 minor，输出结构不兼容升 major。旧正文由 Git 追溯，不复制进新配置或用户记忆。

## 当前冲突与新能力接入

现有测评对话自行判分、数值掌握展示、计划时间总量、摘要自由润色等仍有已登记差距；不以本轮版本化当作修复。偏好/完整目标结构未接入时不擅自修改输出 schema，防止抽取结果被现有模型静默丢弃。
后续新增目标澄清/矩阵、来源检索提取、画像驱动计划、计划自审核、工具 Decision、证据判定、周期回顾分别登记独立 ID/版本/输入与输出契约。没有对应服务和有效性校验时不加入生产调用；不建立空 prompt 占位。Decision 只提出工具名/参数，不能输出可信主体或授权。

## 测试与验收

当前离线测试覆盖完整注册、正文变更检测、未知 ID 拒绝、组合 system 片段识别和不复制私有正文。补充模型质量评测使用开发集；独立验收集不用于 prompt 调优。prompt 存在/检查通过不等于教学、证据或流程已经正确。
