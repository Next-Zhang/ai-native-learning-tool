# 产品数据管理与访问设计

日期：2026-11-01。状态：目标设计、尚未实现。产品数据由产品系统管理，各领域拥有自己的规则；Agent 的存取通过对应领域 Router 判断，不能直连数据库或任意修改数据。关联设计见 [产品系统设计](system-design.md)、[Agent 运行设计](agent-runtime-design.md)、[Workflow 设计](workflow-design.md)。

## 1. 命名与职责

“产品数据管理与访问层”是记忆、学习业务/证据、资料、运行记录和评估等数据服务的统称，不再使用“Agent 长期记忆”代表产品数据仓库。其中偏好、历史交流和接续摘要的所有者命名为“用户与会话数据服务”。
数据所有者负责语义、有效状态和生命周期；存储适配器负责可靠读写。Agent 访问接口以类型化操作呈现，不提供通用 SQL、文件路径、表名或 set_state。各领域 Router 是独立策略模块，可部署在同一 Python 进程中，不要求多个数据库或微服务。
应用层访问入口负责识别请求、认证上下文和分发；具体读写资格由对应领域 Router 与所有者规则共同决定。统一入口不能绕过领域检查，也不成为新的总业务决策器。

## 2. 领域 Router 与 Agent 权限矩阵

“可读”均指当前主体、当前授权 Way、当前任务所需且字段投影后的数据，不代表整表可读。业务合法性和数据权限均须满足。

| Router | 所属数据 | Agent 读取范围 | Agent 写入方式 | 禁止事项 |
|---|---|---|---|---|
| LearningRouter | 目标/矩阵、计划、任务、提交、确认状态与进度 | 可读当前有效状态及当前流程必需版本；历史提交按关联回取 | 可创建草案/提出变更/请求确认；激活与推进由业务命令依据真实确认和有效判定处理 | 自授确认、直接改进度、覆盖原始提交/标准 |
| EvidenceRouter | 判定、帮助、独立/保持证据、画像、争议 | 可读与当前教学/判定/回顾相关的证据与边界；原始作答按需要回取 | 仅提交判定候选或争议/纠正请求；服务验证来源、题目/提交/量规和权限后生成有效记录 | 从摘要写能力结论、跨目标继承、直接改画像或伪造独立性 |
| UserSessionRouter | 偏好、约束、历史对话、接续摘要、过程性未解决问题 | 可读相关有效偏好、摘要与引用原文；不是全部对话默认注入 | 提交带来源候选；Router 核验后保存/合并；删除按真实用户请求和范围执行 | 推断覆盖明确声明、摘要伪造业务事实、自由删除用户历史 |
| ResourceRouter | 资料正文/来源/版本、访问状态和采用关联 | 可读合法取得且任务相关的内容；共享资料不携带他人采用记录 | 工具来源可写资料，Agent 可提出选用/关联；系统核验来源及版本 | 编造引用、任意本机文件读取、通过资料访问其他用户数据 |
| RuntimeRouter | run/step、工具观察、检查点、取消/暂停状态 | 条件可读当前运行及明确关联恢复任务的业务投影 | Agent 可提出行动和停止意图；执行状态/成功标记/检查点由运行控制器写入 | 修改历史动作状态、复活取消请求、读取其他运行原始调试信息 |
| EvaluationRouter | 调用与评估记录 | 默认不向 Agent 开放原始日志/数据集；有明确用途和能力授权时可读自身运行的有限统计投影 | 执行层提供事件，独立服务接收；Agent 无权写成功率或改评估结论 | 读验收标签/holdout 答案、跨用户统计明细、删除失败记录改善指标 |
| IdentityPolicyRouter | 账号、授权策略、凭据与系统配置 | Agent 无权读凭据、令牌、密码、私钥、完整策略或管理配置；仅获当前操作允许/拒绝和必要能力描述 | 只允许可信身份/管理流程执行，Agent 不获写工具 | 更改主体身份、扩大能力、读取密钥或自行修改政策 |

用户输入了凭据也不会赋予 Agent 存取系统密钥库的权限。身份/策略模块向执行器提供可信主体和决策，不向模型泄露执行凭据。
Router 按数据领域而不是按文件格式划分；一个综合请求可包含多个领域，但每个子请求分别判断。不存在“已经通过 LearningRouter，所以证据和日志也全部可读”的继承权限。

## 3. 请求、判断和响应

DataAccessRequest 包含 operation、领域类型、对象/版本引用、字段要求、用途、调用身份与当前运行。可信主体、Way 所有权和实际能力由服务器/当前本地适配器补入，不信任模型传入的 principal、owner_id 或 purpose 授权声明。用途必须与运行实际子目标和已授能力匹配。

判断顺序为：

1. 校验已认证主体和调用能力；本地原型采用可信本机主体，不因此宣称在线认证已实现。
2. 选择预先登记的领域 Router，拒绝未知领域或操作，不按字符串拼接路径或表名。
3. 在访问存储前约束主体、Way、对象关系；对象 ID 不是访问凭据，模型给出别人的 ID 不构成访问权。
4. 检查当前用途、Workflow 前置条件、所需字段、数据有效性与来源资格；写入还检查版本、幂等身份、确认及删除代际。
5. 读取只返回允许字段和适用版本；写入产生批准的领域命令，由所有者执行一致提交。
6. 返回允许、裁剪、需要确认、需要依据、冲突或拒绝，以及安全的原因类别、实际生效/保存状态。

默认拒绝未定义操作和字段。权限存疑/策略服务故障时不能按全量读取回退。读取被裁剪时显式记录 omitted_fields/missing_requirements；必需量规、提交或帮助记录不可读时不能由模型猜测并正式判定。
缺乏对象访问权时对 Agent 使用统一不可访问结果，不通过错误消息泄露对象存在、归属、标题或正文。内部诊断可保留受限原因码，不把管理信息注入上下文。

## 4. 所有 Agent 数据通道都经过判断

主动查询：Agent 行动请求 → 受控执行器 → 访问分发 → 领域 Router → 数据所有者/存储 → 字段投影 → Observation。
上下文预加载：上下文服务提出类型化子查询 → 各领域 Router → 合并允许结果并执行整体预算 → ContextBundle。上下文服务不是绕过权限的高权限读取器；它不能先读取全部私人数据再仅在提示词中说明“不要看”。
工具返回值：涉及已存产品数据的工具也走 Router；外部检索结果按资料来源和输出投影过滤，不把访问令牌、原始异常或完整响应头返回模型。写入失败时不能在观察或最终回复中报告成功。
流式进度、缓存、摘要、搜索命中、运行恢复和导出也遵守同样规则。缓存至少按主体、Way、用途、允许字段、策略版本及对象版本区分；检索前先限制作用域，不能先检出他人内容再交给模型过滤。
上下文最终注入前核对依赖版本和授权是否仍有效；授权撤销、删除或策略变化使相关缓存及运行快照失效。数据正文不会因先前一次允许就永久保留访问权。

## 5. 写入、跨域命令和生命周期

Agent 发起的 write 是“申请执行某个领域操作”，不是获得存储写权限。明确偏好候选可在规则允许后自动生效；计划生效、任务验收推进、纠正与用户删除使用相应确认规则。不是所有写入都需要人工确认，也不是所有候选都能自动生效。
多领域命令由应用服务协调，例如用户确认任务结果后写验收状态、有效证据与进度。当前本地存储可在同一提交中实现一致性；未来跨存储时需明确事务或可恢复流程，不把多个 Router 分别成功当作整体成功。失败时返回实际完成和待恢复范围，禁止重复应用。
各所有者拥有保留、修订和删除策略。跨域清理由应用服务核验用户范围并编排，不允许一个 Router 独自删除其他领域正文。删除/纠正必须使相关派生内容、索引和缓存失效；后台旧结果仍需通过版本/代际复核，不能使内容复活。
原四模块中的分类、来源、原文回取、生命周期机制按领域复用；狭义 UserSessionRouter 不成为整个产品数据总 Router。

## 6. 可验证场景

| 场景 | 必须结果 |
|---|---|
| 相同用户、错误 Way 或猜测其他对象 ID | 拒绝，无正文/存在性泄露；不退回全局查询 |
| Agent 要求读取凭据、策略原文或验收标签 | 拒绝；不能通过上下文服务、摘要、缓存或工具观察绕过 |
| 当前任务原始提交获准，辅助字段无关 | 返回必需原文与允许字段，无关私有字段不返回 |
| 必需证据因权限/删除不可得 | 明确不完整，不能正式判定或伪称核验 |
| 模型写 confirmed=true、score 或 completed | 作为不获授权的候选拒绝；真实业务确认仍独立处理 |
| 用户明确偏好且来源匹配 | 在领域规则允许后保存，不额外增加无必要人工确认 |
| ToolResult 含密钥、他人片段或敏感异常 | 执行层过滤，禁止进入模型和最终输出 |
| 授权/版本在读取后变化，旧请求晚返回 | 拒绝过期应用、清缓存，重新获取当前合法视图 |
| 跨域写入部分失败 | 报告最后可靠状态并可恢复，不重复推进或假称整体保存 |
| 评估原始日志/标签读取被拒，受限自用统计获准 | 只返回授权的统计投影，详细统计口径由后续评估设计定义 |

上述为目标验收要求，未实现或执行。具体字段白名单随各领域操作契约维护，新增字段默认不自动向 Agent 开放。当前仅设计接口，不新增在线账号/管理员功能或实际 Router 实现。
