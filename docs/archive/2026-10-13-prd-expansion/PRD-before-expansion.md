# AI Native Learning Tool 产品需求文档

文档修订：2026-10-13。产品方向已由项目负责人明确为持续学习；软件实现仍为 v0.18。
本文定义产品要求。实现状态见 [交付清单](delivery.md)，证据见 [验证报告](validation.md)。

## 1. 产品定义

面向有明确能力目标、愿意持续投入练习的自学者，提供一个能跨多次学习接续进度、通过产出判断表现、据此调整后续安排的个性化 AI 学习教练。

用户希望在一段时间内逐步形成可独立运用的能力。产品将长期目标拆成里程碑，再落实为每次可执行的任务；依据表现反馈、补强和复验。

当前为个人项目、单用户本机原型，先自用验证，再考虑少量试用。商业化、公开发布与多用户服务暂缓。

## 2. 用户、问题与价值假设

目标用户：已经选定一个技能方向或能力目标，希望持续练习，但难以自己判断起点、安排下一步和追踪进步的人。

典型场景：用户希望逐步掌握 Python 数据分析，每次投入约 30 分钟；学习跨多次进行，间隔或中断后希望直接接续；遇到错误时需要知道原因，之后还要验证是否真正改善。

| 问题假设 | 希望获得的结果 |
|---|---|
| 教材与建议缺少针对个人起点的执行顺序 | 清楚下一次练什么、为什么 |
| 看懂内容后难以判断是否能独立应用 | 用具体产出验证本次表现 |
| 学习间隔后需要重新解释目标和进度 | 回来即可接续任务和薄弱点 |
| 计划与实际能力、时间发生偏差 | 后续安排随表现和容量调整 |
| 一次成功后仍可能遗忘或无法迁移 | 在后续学习中复验并记录证据 |

以上是待验证的问题假设；本次定位调整不构成用户研究结果。
需要比较的替代方案包括课程、个人学习记录，以及带历史或记忆能力的通用 AI；不预设它们都“无状态”。

核心价值假设：围绕同一目标持续记录与调整的闭环，能够帮助用户获得可观察的独立应用能力，并降低接续和规划成本。

## 3. 核心体验

首次：澄清能力目标与用途 → 了解起点 → 制定路线图及近期安排 → 用户确认 → 开始任务。

每次：恢复目标与进度 → 给出当前任务 → 讲解或练习支持 → 用户提交 → 验收及解释 → 更新学习记录 → 明确下次接续点。

跨次：根据薄弱点、练习表现和可用时间调整近期安排；对已有证据安排适当复验。

中断后：保留目标、任务与有效提交；再次进入时说明当前进度，支持继续或调整安排。
目标结束时：回顾已有证据与剩余不足，明确结束或建立下一个目标。结束不能只依赖模型一句“你已掌握”。

任务是执行单元，里程碑承载阶段目标，路线图承载持续学习目标。完成一次任务只证明该次任务表现。

## 4. 用户需求与验收条件

沿用既有 UR 编号便于追溯；UR-01、UR-04 按持续学习重述，UR-13、UR-14 新增。
需求真实性均待用户验证；本表不记录实现状态。

| ID | 用户需要什么 | 可观察的验收条件 |
|---|---|---|
| UR-01 | 围绕我的能力目标持续学习，知道每次做什么 | 路线图、里程碑和当前任务关联清楚，用户能说明任务与目标的关系 |
| UR-02 | 知道本次表现及其依据 | 判定绑定实际题目/任务和提交；区分完成、未完成与无法判断 |
| UR-03 | 理解评分、质疑并纠正错误 | 展示依据；争议可进入复核或重试，系统错误不计为学习失败 |
| UR-04 | 根据现实变化调整节奏，暂停或结束 | 调整容量后后续安排符合预算；暂停可接续；目标结束有明确收尾 |
| UR-05 | 下次直接接上，保留目标、进度和薄弱点 | 重启及跨次回来不重复初始化，能追溯重要学习记录 |
| UR-06 | 能力不足或服务失败时得到诚实说明 | 明确区分无资料、模型故障与用户未完成，不写入虚假能力证据 |
| UR-07 | 用少量关键问题建立可执行目标 | 每次澄清 1～2 个关键问题，说明缺失信息为何必要 |
| UR-08 | 对重大变更拥有确认权 | 改目标、实质重建计划、删除记录、人工标记掌握需明确确认；拒绝不执行 |
| UR-09 | 能查看及控制个人学习数据 | 明确清理范围、摘要/归档/备份/日志去向；被清理内容不继续作为对话记忆 |
| UR-10 | 在不同技能领域获得可执行安排 | 分领域验证任务质量与判定依据，不以能生成文字证明领域普适性 |
| UR-11 | 获得适度的进步反馈 | 反馈基于真实记录，不改变验收结论；后续评估 |
| UR-12 | 通过讲解巩固理解 | 讲解产出有明确要求并能获得反馈；后续评估 |
| UR-13 | 在后续学习中复验薄弱或久未练习的能力 | 复验绑定已有知识点；记录新的表现，不能只生成提醒文字 |
| UR-14 | 看清一段时间的进步与不足 | 区分任务完成记录、独立应用证据与待复验项，不将完成率等同掌握度 |

## 5. 目标与个性化

目标应包含：希望形成的能力、实际用途、目标范围和成功的样子。具体工作任务可作为练习场景。
时间容量按每次可投入时长表达；每周次数和期限可为空。自评作为起点参考，不作为掌握证据。

放行原则：能力目标与本次可用时间明确，目标范围及成功标准已澄清到足以出题或生成任务。
不能仅因用户无法自评或没有截止日期而阻止持续学习。这是目标要求，与现有四项必填实现的差异见交付清单。

| 画像维度 | 内容 | 应改变什么 |
|---|---|---|
| 起点 | 自评、测评及练习证据 | 初始难度与补强顺序 |
| 目标用途 | 能力目标、范围、应用场景、成功标准 | 内容范围、练习场景与终点 |
| 时间节奏 | 单次时长、可选频次与期限 | 每次总任务量和近期安排 |
| 学习偏好 | 讲解、练习和反馈偏好，可选 | 表达方式与练习形态 |
| 表现进度 | 有来源的任务结果、错误和复验记录 | 后续安排与阶段回顾 |

偏好采集不得阻塞主流程。每条被采集的信息应有消费点；原始预算不能静默扩大。
一次学习内全部任务的预计总量应符合本次时间预算。容量变化应被明确说明。

## 6. 判定、记忆与用户控制

- 任务先有产出要求和可检验标准，再开始练习。
- 题目、提交、结果与知识点之间应可追溯；系统故障和无效模型输出不转成能力不足。
- 判定性事实来自测评、验收或经确认的纠正；摘要只帮助接续，不产生掌握结论。
- 区分本次完成与能力掌握；独立性、迁移或跨次保持不足时，结论应保留边界。
- 允许用户质疑判定并重试；纠正需保留来源，不能静默改写历史。
- 自动调整须说明原因。目标范围或计划实质变化需要确认；新生成任务不因此前确认而无限授权。
- 数据清理需明确保留和删除的对象；备份与诊断日志的保留应告知用户。
- 学习内容会被发送到第三方模型 API；扩大小范围试用前核实供应商留存条款与使用边界。

## 7. MVP 范围

核心范围：单用户围绕一个目标跨多次学习；目标澄清、起点测评、双层安排、任务与验收、进度接续、表现记录、薄弱点补强、最小复验、阶段回顾及目标收尾。
先通过 CLI 验证，Web 展示在闭环可靠后安排。代码存在与满足以上体验的差距统一见交付清单。

暂缓：自动提醒、账号与多用户、商业化、复杂复习算法、用户自带计划导入、趣味化体系、独立 teaching 模式、动态多 Agent 编排。
本地 RAG 保留为可选实验；是否需要联网或知识库，以内容正确性和来源需求验证为依据。

覆盖不同领域是能力边界验证，不承诺任意领域均有同等质量。医学、法律等高影响用途需要另行审查。

## 8. 成功标准与验证方向

| 指标 | 操作定义 | 决策用途 |
|---|---|---|
| 连续学习接续成功率 | 跨次返回后能接续有效进度的次数 / 被观察返回次数 | 检查连续性 |
| 独立应用表现 | 对未见过的相似任务，在记录帮助程度后按量规评定 | 检查能力变化 |
| 复验表现 | 对已记录知识点进行后续复验的结果 | 检查保持与补强 |
| 任务完成率 | 完成任务数 / 下发任务数 | 辅助观察执行，不能代表掌握 |
| 判分一致率 M-01 | 有效判定与人工复核一致数 / 已复核有效判定数 | 检查评分质量，同时报告故障率 |
| 可靠性 M-02 | 关键链路通过率；错误不得污染能力记录 | 发布硬门槛 |
| 成本 M-03 / 延迟 M-04 | 每轮总 token、成本及端到端耗时 | 控制持续使用负担 |
| 注入阻断 M-05 | 已列攻击样例的阻断比例 | 仅支持已测边界结论 |

具体样本、时间窗、阈值与执行记录由验证报告维护。学习效果、留存和成本预算当前均无充分基线，不填造数值。

正式试用前：关键故障与授权路径通过，删除语义正确，真实模型流程可重复，判分经过人工复核；明确已知限制和数据去向。
公开发布、商业化及多用户不在本次批准范围。
