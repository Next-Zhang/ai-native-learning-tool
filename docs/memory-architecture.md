## 1. 目标作用域与四个模块

学习路径（Way）是围绕一个持续学习目标的记忆作用域，可以跨越多个实际学习会话。当前会话、本次 ReAct 运行都属于该 Way；不能每次启动就建立新目标作用域。
1.0 明确当前单路径的目标归属、会话及记录身份，不实现多个 Way 的管理界面、切换或通用多路径调度框架。未来多路径沿用相同归属规则，每次一个激活路径。

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| 记忆 Router | 接收带来源的候选，校验类别、作用域、有效性与写入资格；返回接收、拒绝或待核实及原因，分发到对应记录类型 | 不凭模型判断直接修改计划确认、任务进度或能力结论；不自行执行物理落盘 |
| 记忆存储 | 保存及查询记录、版本与引用；提供一致读写和删除；维护当前有效视图与必要历史 | 不推断学习者能力，不决定教学策略；不是另一份独立事实来源 |
| 上下文组装与注入 | 根据当前任务读取当前 Way 的有效信息，处理重复、争议与预算，必要时回取原文，带来源组装输入 | 不用摘要替代必须核验的提交，不把外部文本升级成系统指令 |
| 记忆生命周期管理 | 按规则合并、标记失效、压缩和清理；检查依赖、使派生内容更新或失效，并同步索引/缓存 | 不把全部历史永久保存，不凭模型的主观重要性删除能力依据 |

主链：输入/执行事件 → 候选提取 → Router → 存储 → 按任务读取与上下文组装 → Agent。
生命周期管理通过同一存储入口执行更新和清理。四个模块共享记录及版本，不各自维护互相竞争的事实副本；1.0 不要求额外的记忆管理 Agent。

## 2. 数据分类与归属

| 类型 | 内容与依据 | 归属与权威边界 |
|---|---|---|
| 业务状态及其关联 | 已确认目标/矩阵、计划版本、任务、提交、确认与恢复点 | 当前 Way；业务状态模块负责改变，记忆读写引用该状态而非另建副本 |
| 用户记忆 | 时间安排、约束、偏好及其来源/适用范围 | 默认当前 Way；用户明确声明优先于模型推测，本次要求与长期偏好分别记录 |
| 学习证据 | 实际题目与提交引用、标准版本、有效判定、帮助程度、时间、复验和争议 | 当前 Way/能力点；有效表现作为判断依据，自评/摘要不是独立证据 |
| 会话记忆 | 原文、摘要、未解决问题、下次接续点 | 当前 Way/实际会话；摘要是派生辅助，可回取原文但受保留策略限制 |
| Agent 工作记忆 | 子目标、已尝试动作、工具结果引用、待办、暂停与退出原因 | 当前 Way/运行；服务局部 ReAct，结束后转存有用结果并回收临时记录 |
| 参考资料 | 真实来源、内容或引用、访问状态、适用能力和采用理由 | 采用关系属于当前 Way；未来公共资料内容可共享，但不共享各路径的结论和授权 |

未来共享偏好只收纳明确适用于所有目标的信息，不从单路径行为自动推广。跨路径证据复用另定，不因主题相似自动继承能力结论。评估记录可独立存储并关联 Way/会话/调用，不作为个人能力记忆。

## 3. 写入与存储原则

已知类型的业务事件直接按来源路由，无需额外模型分类。自然语言可由模型提取多条不同类型的候选，但必须保留原消息引用；模型输出不能自行授予来源可信度、用户授权或有效判定资格。
确定性规则检查来源与类型是否匹配：用户声明可更新偏好；摘要中的“已掌握”不得成为能力证据；调用故障只形成运行事实；计划确认仍走业务确认规则。未知、冲突或缺必要依据的候选不静默升级成有效事实。

重要记录应可独立寻址，包含稳定 ID、当前作用域、类型、来源引用、发生/记录时间、有效状态及版本；按类型关联能力点、任务、提交、量规、原文消息或运行。发生时间不足时标记未知，不能用迁移或处理时间伪造复验间隔。
当前有效视图与必要历史分开：保留历史是为接续、复核和未解决依赖服务，受类型保留规则限制，不是永久事件仓库。摘要、画像、计划等派生结果关联所依据的记录和版本。

1.0 可以沿用单文件 JSON，并经统一入口串行一致写入；不因四模块拆分而拆成四个互不协调的文件。关联结果与应用标记应整体可靠保存，避免部分生效。读操作使用一致状态快照；写操作检查所依据版本，迟到结果不覆盖新声明、计划或删除后的状态。未来有复杂查询/并发需求再评估 SQLite 等，当前不增加数据库依赖。
存储的原子落盘不等于已具备业务事务、幂等应用或多进程并发控制；这些需要分别实现与验证。

## 4. 按任务读取、原文回取与上下文预算

读取先限定当前 Way，再检查有效状态、版本、任务关联与时间范围；先精确定位，再条件筛选，最后按需使用关键词或语义检索。未来公共资料读取须保留来源，不能借共享资料混入其他 Way 的用户记录。

| 操作 | 必需信息 | 按需补充 |
|---|---|---|
| 判定提交 | 实际任务/标准版本、原始提交、帮助记录 | 对应参考资料、相关澄清原文 |
| 生成计划 | 目标/矩阵、有效证据与未测范围、容量、偏好 | 近期过程摘要与资料 |
| 中断返回 | 最后可靠状态、未完成任务、待提交/待确认事项 | 最近摘要及所引用原文 |
| 周期回顾 | 周期内结果、独立/复验证据、容量变化与争议 | 相关会话和旧计划版本 |
| 恢复 ReAct | 子目标、已执行动作、工具结果引用、暂停原因 | 待办所需资料 |

原文以稳定消息 ID、实际会话、时间与任务关联保存。摘要引用消息或消息范围，取回时返回对应原文和必要相邻上下文；按 ID、任务或会话查找不依赖向量检索。未知 ID、已清理内容、读取失败要明确返回，不能编造替代原文。
当前代码只加载整个 JSON 后读取近期原文，archive_segments 返回分段副本；目标级自动回取与消息索引尚未实现。

上下文优先包含必需记录，再加入辅助内容。预算针对整个请求，包括系统规则、工具定义、资料、摘要、历史、当前状态和用户输入；字符数估算不能视为模型 token 硬上限。预算/预留输出数值在实现设计中确定。
必需提交或标准缺失/超限时，返回明确的不完整状态，分段处理或请求缩小范围；未完成核验不得正式判定。摘要及外部材料带来源/可信度标签，不提升成操作授权；消息位置不是可信度的保证。

## 5. 冲突、有效性与派生失效

按信息类型选择依据，没有“最新文本永远优先”的通用规则。用户自评与有效表现分别保存；两次表现不同可以是变化而非冲突；本次约束不直接覆盖长期偏好。
同一适用范围的新声明可替代旧值；正式判定与摘要不符时修正摘要；原证据纠正后画像重新计算，依赖它的计划和摘要须重新检查或标记过期。重大计划变更仍按 PRD 确认。
无法自动消解时保留待核实/争议状态，避免用于新增能力结论；只在需要用户决定或影响当前任务时提出具体问题。写入规则模块识别冲突，存储维护版本，生命周期模块处理失效/依赖，上下文模块呈现边界。

## 6. 生命周期、清理与压缩

保留判断依次检查明确用途、当前有效性、未解决依赖及可替代性。产品规则定义各类型条件，代码执行；模型只提供重复/合并候选，用户可以纠正和要求删除，不由主 Agent 自由裁决。

| 对象 | 清理规则 |
|---|---|
| 重复偏好或记录 | 核对适用范围后合并，保留必要来源，不把不同场景混为一条 |
| 被替代的旧值 | 退出正常读取；无追溯用途、未解决依赖或保留要求时删除 |
| 过期派生摘要/草稿 | 更新、重新生成或删除；不能继续作为当前有效内容 |
| 已结束工作记忆 | 结果、必要来源和未解决事项转存后回收临时记录 |
| 历史学习证据 | 按用途和保留策略处理，不因较旧/后来失败直接判作失效；降采样不能继续宣称保有已丢失明细 |
| 原文与资料 | 必需信息已可靠提取且无未解决引用后按策略清理；暂时访问失败不自动等于资料无价值 |

写入时去重与替换；任务/会话结束时回收临时内容；周期回顾整理冗余；用户删除即时进入对应流程。无需增加常驻调度服务或三个新的用户清理入口。
正常自动清理遇到有效依赖时暂缓，或先更新派生结果；不能留下需要引用却不可取回的依据。用户明确要求删除时不能因依赖无限保留，应同步移除或降低相关结论、处理派生副本并说明影响。清理通过统一入口作用于当前 Way，索引/缓存/摘要引用同步处理；异步旧结果不能使已删除内容复活。备份、trace 与第三方范围仍按 PRD BR-11 说明。
压缩保留未完成任务、待确认项、关键约束、接续问题和证据引用。L1→L2 需要明确移交信息，不能直接清空尚未进入定稿的接续内容；待压缩原文未被完整处理时不得静默当成已处理。
开发默认数量、容量保护与压缩阈值已由 [开发规格](memory-implementation-spec.md) 具体化，属于可调工程起点，不是已实测的最优值。普通窗口之外按有效依赖保护必要记录；这些规则不能代替修复已确认的裁剪失效，也不能破坏上述保留用途。

## 7. 与 Agent 评估的交界

工具调用与检索失败须保有用于后续次数/成功率统计的执行结果和必要关联信息。调用发生时提供评估事件，不能等到记忆清理时才统计；临时工作记忆清理不得连带删除评估所需记录。
评估记录不当作能力不足证据。事件字段、重试统计口径、评估数据保留策略及测试协议留待专门的 Agent 评估设计，不在本次设定；现有 metrics/trace 不因此被认定已满足全部要求。用户明确删除个人数据时，评估记录也遵守相应数据控制范围。
