## 3. 持续学习验证计划（未执行）

先选择一个能力目标，让同一用户分多次学习并至少经历一次中断后返回。
记录任务、帮助程度、有效判定、复验和接续情况。Python 数据分析可作为首个自用场景。
第二个领域的样本用于检验内容边界，不作为证明任意领域普适性的依据。

| 问题 | 方法 | 判断 |
|---|---|---|
| 接续是否可靠 | 保存后退出；另一实际会话回来；核对任务、提交、薄弱点与下一步 | 不重复初始化、不丢有效进度 |
| 是否形成独立应用能力 | 记录帮助程度，使用未见过的相似任务及人工量规 | 不用原任务通过率替代 |
| 复验是否有效 | 在后续会话复验同一知识点，关联旧证据 | 能识别保持、遗忘或改善 |
| 是否确实需要该产品 | 询问过去学习经历，观察持续使用，与现有课程/通用 AI/笔记方案比较 | 不能通过引导提问证明需求 |
| 计划是否适应现实 | 主动缩短容量或暂停，再返回 | 安排符合预算、变更原因可见 |

O-07 自用观察已确定：项目作者围绕同一目标至少 5 次实际会话，观察跨度至少 7 天，包含中断返回及至少间隔 16 小时的独立复验；会话、时间与配对任务口径以 PRD 第 8.3 节为准。开始前记录起点与量规，后续记录未见可比任务的独立表现、帮助、错误、接续和复验；先测基线，不设提升百分比硬门槛。
当前未执行，未获得满足该协议的运行记录；历史累计 5 次 API 会话不能代替本次观察。外部用户研究的样本规模与比较设计另定。
小样本熟人试用有选择偏差；数次学习可验证机制，不能证明长期学习效果或因果增量。
