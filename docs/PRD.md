# AI Native Learning Tool 产品需求文档（PRD）

> **一句话**：面向**任务驱动的即时学习者**的个性化学习教练——它从**起点、用途、节奏、偏好、表现**五个维度理解你，生成一份**可执行的方案**；你做完它验收，方案随你的表现滚动调整。
>
> **结构**：按「**需求 → 方案 → 验收**」三幕组织。第一幕讲为谁解决什么问题；第二幕讲用什么机制解决；第三幕讲怎么证明解决了。
>
> **本文只写产品**——要什么、为什么、怎么验证。**技术实现（模块划分、数据结构、接口、文件）不在本文**，见 [architecture.md](architecture.md)。
>
> **状态标记**：五档 **已验证 / 待验证 / 待定 / 暂缓 / 不适用**；实现状态另标 **✅已实现 / 🔸部分 / ⬜待实现**（两者不混用）。
> **项目模式**：个人项目模式——个人负责、验证具体用户问题与最小可行方案、尚未承诺规模化。**第一版以 MVP 为核心对象**。

| 术语 | 含义 |
|---|---|
| **任务驱动的即时学习者** | 本产品的**目标用户**：因为**要完成一件具体的事**，而需要学会某个领域里**一小块**内容的人。特征：① 有外部时间约束；② 只需"够用"，不要系统学完基础；③ 要能判断自己是否真的会 |
| **用户画像** | 系统对学习者的完整认识，含**五个维度**：起点水平 / 目标用途 / 时间节奏 / 学习偏好 / 表现进度。**这是"个性化"的唯一载体** |
| **自评 vs 判定** | **自评**=用户自己说的水平，**仅作测评起点**；**判定**=经测评或验收确认的结果。**只有判定才能决定"跳过什么"** |
| **方案（Plan）** | 结构化的、可执行、可追踪的学习安排（里程碑 + 当前执行窗口 + 任务）。**区别于"一段建议文本"** |
| **即时学习（just-in-time）** | 为完成眼前任务而学，学的是"刚够用"的那一小块，不是完整课程 |
| **UR / S** | UR=用户需求（要什么）；S=方案要素（怎么满足） |
| **HITL** | Human-in-the-Loop：不可逆动作（重建方案 / 改目标 / 删历史 / 标记已掌握）必须经用户确认 |
| **workflow / agent** | Anthropic 的区分：workflow=由预定义代码路径编排；agent=模型动态决定流程。本项目为 **workflow + 模型辅助** |
| **rubric** | 评分量规：事先定义的判分维度与标准 |

## 一页速览

**产品一句话**：面向**任务驱动的即时学习者**的个性化学习教练——你说"我要做成什么事"，它从**起点、用途、节奏、偏好、表现**五个维度理解你，给你一份**能执行完的方案**；你交出产出，它验收并把结果记进画像，**方案随你的实际表现滚动调整**。

**要解决的问题**：因为一个具体任务要学一小块技能的人，在现有方式之间拿不到「**针对我的任务 + 被验收 + 能接续**」的闭环：
- ① **找教程**：选择成本高、多数不匹配、周期长、缺少练习；
- ② **通用大模型**：能答，但**不追踪你、计划静态、不强制产出**；
- ③ **课程平台**：体系完整但**周期太长**，为完成任务而学的人推不动。

**需求 → 方案 → 验收 总表**：

| 需求（用户要什么） | 方案（系统怎么满足） | 验收（怎么证明） | 本期 |
|---|---|---|---|
| **UR-01** 针对**我的具体任务**学，不按学科体系从头学 | **S-12 双层方案**：路线图 + 执行窗口；任务围绕"用途" | T-01 | 🔸 |
| **UR-02** 知道"我到底会不会"，不是"感觉懂了" | **S-01 验收**：结构化判定 + 证据要求；**强度由代码定，模型不得放宽** | M-01 | 🔸 |
| **UR-03** 知道它凭什么这么判，不同意时能纠正 | 展示完成度 / 错误类型 / 理由；可反驳、可重做 | 理解测试 | ✅ |
| **UR-04** 不被计划绑住：能换任务、能缩短、能结束 | **S-14 例外转移**（已登记的合法路径） | T-11 | ⬜ |
| **UR-05** 记住我学到哪、薄弱在哪，**下次直接接上** | **S-17 用户画像**（五维度）+ 表现历史 | 聚合单测 | 🔸 |
| **UR-06** 能力不足或没资料时**诚实降级**，不编造 | **S-04 联网检索**标来源；失败**保持当前阶段** | M-05 / T-06 | 🔸 |
| **UR-07** 我信息没给全时，先问关键问题 | 一次只问 1~2 个；必填齐才放行 | T-02 | ✅ |
| **UR-08** 换目标 / 重建方案 / 删历史**必须先问我** | **S-08** HITL 确认门 | T-10 | ✅ |
| **UR-09** 我能控制和删除自己的数据 | 清空历史、完全重置，带备份 | 单测 | ✅ |
| **UR-10** 同一产品覆盖**不同领域** | **不限领域**（由目标驱动）+ **两领域验证** | T-01 分领域 | 🔸 |
| **UR-11** 学习过程**更有趣**（后续） | **S-15 趣味化反馈**（仅反馈层） | 后续 | ⬜ |
| **UR-12** 想通过"讲给别人听"来巩固（后续） | **S-11 teaching** | 后续 | ⬜ |

**方案总览一句话**：**固定流程（workflow）+ 模型辅助**——阶段转换由**代码守卫**决定（一次只推一档），模型只在阶段内做内容生成与结构化判定。**验收与授权不可让渡。**

**本期范围**：让一条闭环跑通，并用**两个差别很大的领域**（如编程 / 心理学）各验证一遍，以**证明领域无关**。
**当前基线**：**181 个测试**（173 通过 + 8 跳过）；累计 **5 次真实 API 会话**，闭环完整推进。

**最大未验证假设**：**"有状态的闭环"相比"无状态的 AI 建议"能带来可观察的学习效果增量**（**待验证**，见 1.5）。

## 1.2 用户、场景与问题

**主要用户**：**任务驱动的即时学习者**——因为**要完成一件具体的事**，而需要学会某个领域里**一小块**内容的人。

| 特征 | 说明 |
|---|---|
| **触发是事件，不是状态** | "我要用 Python 处理一份数据"、"我要下周做一次团队演讲"——**有明确的卡点** |
| **有外部时间约束** | 工作 / 项目 / 交付日期；**放弃的代价是事情做不完** |
| **只要"够用"** | 不接受先系统学基础；要的是**能解决眼前问题的那一小块** |
| **要能自证** | 需要知道自己"到底会不会"，而不是"感觉懂了" |

**典型场景**：

> 我需要用 Python 完成一个数据处理的工作 → 我就要去学 Python 的数据处理部分 → 我既然是为了完成工作，就没有时间进行长周期的学习。

**当前做法的痛点**：

| 现有做法 | 痛点 |
|---|---|
| **找教程自学** | ① 选择教程花费大量时间；② 教程不适合我（难度、范围、风格不匹配）；③ **周期长**；④ **无法有效练习** |
| **问通用大模型** | 能立刻答，但：① **不追踪我**（每次对话孤立）；② **计划静态**（生成一次不随表现调整）；③ **不强制产出**（看懂≠会做）；④ 不知道我上周错在哪 |
| **课程平台** | 体系完整、内容权威，但**周期太长**，为完成任务而学的人推不动 |

**由此引申出的一类问题**：

> 我想学习**一个领域中的一个技巧或一小部分内容**，但不想花大量时间去了解或学习基础——**我很难找到一个能进行有效学习的方式**。

**关键场景（机制已跑通，已验证）**：

**说出要完成的任务 + 每次能给多久** → **澄清** → **测评起点** → **生成方案** → **用户确认** → **下发一个任务** → **交付产出** → **验收** → **写入画像** → **下次进来直接接上**。

**边界场景**：模糊目标（"我想学点东西"）、中途换任务 / 换目标、**只想解决一次**、接口超时 / 限流、**领域中无可检验产出的情况**（见 2.3 的"可检验标准"约束）。

**用户真实性**：**全部待验证**（无用户访谈样本）。验证计划见 1.5。

## 1.4 机会、定位与约束

| 字段 | 内容 |
|---|---|
| 个人项目目标 | ① 验证"有状态的个性化闭环"是否有效；② 形成可展示的 AI 产品作品。**不虚构组织战略或市场规模** |
| Why now | 通用大模型"能答 ≠ 会教"，且**无状态**——它给你建议，但不追踪你、不调整你的计划、不强制你产出。**即时学习缺的是"针对我 + 被验收 + 能接续"的闭环** |
| 现有替代方案 | ① 找教程自学；② 问通用大模型；③ 课程平台。详见 1.2 痛点表 |
| **差异化假设** | **"有状态的闭环" 优于 "无状态的建议"**——同样一次问答，本产品**记住你的表现**、**按表现调整方案**、**要求你交出产出**。**待验证** |
| 商业模式 | **暂缓**：本阶段不验证商业化。真实成本 = API + 本机算力；预算上限**待测基线后填** |
| 关键约束 | 个人预算上限（待定）；仅本机验证、数据仅本机；**依赖单一第三方模型**；**验收依赖模型判断**（无客观执行环境）；**验收强度由代码决定，模型不得自行放宽** |
| 依赖与前提 | 第三方模型 API；联网检索服务（待接入） |

**与通用 AI 的正面对比（本产品的立身之本）**：

| 通用 AI 缺什么 | 本产品怎么补 |
|---|---|
| **无状态**——每次对话孤立，不认识你 | 画像跨会话持久 |
| **计划静态**——生成一次，不随你变 | **滚动 = 重估**：按实际速度调整后续安排 |
| **不追踪你**——不知道你上次错在哪 | 画像累积 + 薄弱点优先 |
| **不强制产出**——看懂 ≠ 会做 | **验收是门**：不提交不推进 |

> **注意**：如果"用通用 AI 就够了"被证实，本产品的定位即不成立——这是 1.5 要优先证伪的。

## 1.5 需求验证计划（**待执行**）

> **目的**：UR-01…UR-12 目前**全部缺少用户证据**。本计划用最小成本拿到定性证据，据此决定**是否继续扩展**。
> **状态**：**待执行**（访谈暂缓）。

**要证伪的四个假设（可证伪，按优先级）**：

| # | 假设 | 证伪标志 |
|---|---|---|
| **H1** | 用户确实有"被一个具体任务卡住 → 需要学到刚好够用"的经历，且能说出**具体是哪一次** | 说不出具体的一次 |
| **H2** | **通用 AI 没能替代它**——用户试过 AI，但不满意 | "我用 ChatGPT 五分钟就搞定了，很满意" ← **最危险** |

| **H4** | "**不知道自己到底会不会**"是他的痛点（而不是没时间 / 没动力） | 真实原因是"没时间" → **"验收"就是解错了题** |

**访谈设计（四步）**：

| 步 | 内容 | 状态 |
|---|---|---|
| Q1 研究目标 | **问题验证（Mom Test 式）**——问过去的行为，不问意愿 | ✅ 已定 |
| Q2 目标样本 | **最近 3 个月内被卡过的人** + **换过方案的人**（尤其"从找教程换成问 AI"的） | ⬜ 待定 |
| Q3 约束 | 个人项目 + 熟人；场次与周期待定 | ⬜ 待定 |
| Q4 方法论 | Mom Test + JTBD 视角（每题追一句"那你后来怎么办的？"） | ⬜ 待定 |

**第 0 场：访谈自己**——作者本人即目标用户，其过去的经历是第一份数据。

**成功判据**：听到**具体故事**而非泛泛抱怨；发现**过去行为**而非未来意愿；**3 场以上出现相同模式**；**有让自己意外的发现**（如果全部印证假设，说明问法有引导性）。

**样本局限（必须随结论报告）**：熟人或小样本、非随机、**无对照组**，结论不可外推。

**决策依据**：若 **H2 被证伪**（通用 AI 已够用）→ 重新定位；若 **H4 被证伪**（痛因是没时间）→ 简化流程、把任务切得更小，而非叠加验收机制。

**未验证前不得做的事**：不得据"机制已实现"推断"用户需要它"；不得把 UR 状态从**待验证**改为**已验证**而没有上述证据。

# 第二幕 · 方案

## 2.1 方案总览与架构定性

**核心机制**：一个由**代码守卫**驱动的工作流状态机，把"学一个技能"拆成可验收的步骤，并由**用户画像**驱动个性化。

> **目标澄清** → **起点测评** → **方案生成**（含确认）→ **任务** → **验收** → **写画像** → 回到任务
> 　　　　　　　　　　　　　　　　　　　　　　　　　　└──── **方案随表现滚动调整** ────┘

**分工（一句话）**：模型在每个阶段**内部**负责内容生成与判定；**代码决定是否推进**、以及**验收强度**。

- **架构定性**：**固定流程（workflow）+ 模型辅助**，不引入图编排框架。阶段转换规则只有一处来源，**一次只推一档**，条件不满足则保持原阶段。
- **为什么这样定性**：① 步骤可预测；② "错误推进"的代价需要**硬约束**；③ **验收与授权不可让渡**。
- **核心张力**：**架构上"五脏俱全"、运行时"按需触发"**——不是每轮全链路调用。每步模型调用必须能说明可测收益，否则合并或删除。
- **领域无关**：系统的行为由**用户画像**驱动，**不预设任何领域**。领域差异只体现在"教什么内容"与"任务的完成标准"上，这两者都由模型在目标约束下生成。因此**不需要领域配置机制**（原领域路由方案已删除）。

> **技术实现**（模块划分、数据结构、执行模型、不变量）见 [architecture.md](architecture.md)。

## 2.3 核心流程与系统边界

### 阶段（**5 个**）

| 阶段 | 用户动作 | AI 的任务 | 代码的任务 | 失败与恢复 |
|---|---|---|---|---|
| **目标澄清** | 说出要完成的事 | 一次问 1~2 个关键问题 | 抽取画像；必填齐才放行 | 抽取失败 → 跳过画像，继续对话 |
| **起点测评** | 逐题作答 | 出 3~5 题（一次一题）；逐题判掌握 / 部分 / 未掌握 | 出题兜底；**纯代码聚合** | 出题失败 → 兜底大纲；判分失败 → 保守记"未掌握" |
| **方案生成** | 先看路线图，再确认 | 生成长期路线图 + 执行窗口并请确认 | 守卫"方案已确认"（路线图级） | 生成失败 → 确定性兜底；确认判定失败 → **保持等待** |
| **任务** | 做任务、交付产出 | 每次只给 1 个任务；引导交付 | 按进度取任务；守卫"已交付" | 判定失败 → 保持任务阶段（**绝不把提问当交付**） |
| **验收** | 提交证据 | 按完成标准判定 | 一致性守卫；**代码写画像并回任务** | 判定失败 → 保持验收；未通过 → 保留任务重做 |

> **v0.16 删除的两个环节**：**复习调度**（从未真正存在——无调度、无时间维度；其价值已由"薄弱点优先"覆盖）与**画像更新**（在同一轮内被穿过，用户与模型都看不到它，已并入验收）。
>
> **v0.18 修订**：**复习调度以最小形式回归**——不是独立阶段，而是排任务时的一条优先级规则（**标记待复验**，触发条件 = **连续 8 次单次学习未覆盖**该知识点）。v0.16 删的是"空阶段"，那个判断仍然成立；现在补上的是它当时缺的**序号（时间）维度**。见 2.5.6 与 [memory-design.md](memory-design.md) §7。

### 产品边界

- **能读**：本机状态文件、终端输入。
- **能写**：本机状态文件与备份目录（保留最近 5 份）。
- **不能**：任何外部写动作（发消息 / 改外部系统 / 支付）；无多用户与账号；除模型 API 调用外无网络写操作。
- **外部系统**：第三方模型 API；联网检索服务（待接入）。

### 一条硬约束：任务必须可检验

> **每个任务必须有一个"可检验的完成标准"。**

| 领域 | 可检验的标准示例 |
|---|---|
| 编程 | 代码对给定输入输出正确结果 |
| 心理学 | 用自己的话解释某个概念，并举一个**自己的**例子 |
| 写作 | 写出指定字数，且包含指定要素 |

没有它，验收就是空话，闭环即断。**这条约束本身领域无关**，且它是"个性化方案"的支柱——方案的每一步都必须可被检验。

**配套职责**：目标澄清阶段须能把**模糊目标转成可检验的任务**（"我想学怎么和人相处" → "我下周要做一次团队演讲"）。

## 2.5 数据、记忆与个性化（模块 D）★核心章节

### 2.5.1 用户画像：五个维度

**用户画像 = 系统对学习者的完整认识**，是"个性化"的唯一载体。它必须**同时**满足两条：① 有明确内容；② 每一项都有明确的**使用点**。

| 维度 | 回答的问题 | **用在哪**（改变了方案的哪一部分） |
|---|---|---|
| **a 起点水平** | 他已经会什么、不会什么 | **跳过什么 + 先做什么** |
| **b 目标用途** | 他要解决什么问题、为什么、何时要 | **教什么 + 用什么场景切入 + 深到哪** |
| **c 时间节奏** | 他一次能投入多久、多久一次 | **任务切多大 + 窗口多长** |
| **d 学习偏好** | 他喜欢怎么学、喜欢怎么被反馈 | **怎么讲 + 例子类型 + 反馈语气** |
| **e 表现进度** | 他实际做得怎样、速度多快 | **下一轮改什么 + 速度重估** |

> **判据**：采集了却没有使用点的信息是**纯负担**（占注入长度、占维护成本、占出错面）。每个维度都必须能回答"它改变了方案的哪一部分"。

### 2.5.2 各维度包含什么

**a. 起点水平** —— 分「自评」与「判定」两层：

| 内容 | 说明 | 谁能写 |
|---|---|---|
| **自评** | 用户自己说的水平（如"有一点基础，会写简单脚本"） | 澄清阶段 |
| **判定结果** | **已掌握 / 半懂 / 缺失** 三档知识点清单 | **只有测评与验收** |
| **底层分数** | 每个知识点的掌握度（0~1），用于追踪进步与排序 | 测评与验收 |

> **红线（自评 ≠ 判定）**：
> - **自评**只用于决定**测评从哪里开始出题**；
> - **只有测评 / 验收**的结果才能写入"已掌握 / 半懂 / 缺失"；
> - **跳过教学必须基于判定，不能基于自评**。
> - 理由：若用户自评"我会了"、系统就跳过，而实际他不会——**"以验收为准"这条产品主张当场失效**。

**b. 目标与用途** —— 两个必须分开的概念：

| 内容 | 说明 |
|---|---|
| **要完成的任务** | 具体场景（如"清洗一份销售数据并出月报"）—— **决定用什么场景切入** |
| **所属技能** | 知识范围（如"pandas 数据处理"）—— **决定教什么范围** |
| **动机** | 工作 / 兴趣 / 考试 / 其他—— **决定深度**（为干活 → 够用就好） |
| **期限** | 什么时候要 |
| **成功的样子** | 什么算成功（如"能自己写出脚本，不用每次求人"）—— **决定终点在哪** |

> **"任务"与"技能"必须分开**：前者决定"用什么场景切入"，后者决定"教什么范围"。混在一起会让方案变成泛泛的学科目录。

**c. 时间与节奏**：单次可投入时长、每周大约几次（可空 = 不承诺）、期限弹性（硬 / 软 / 无）。

**d. 学习偏好（v0.16 新增）**：讲解风格（例子优先 / 原理优先）、练习风格（先动手 / 先看懂）、反馈语气（直接 / 温和）。

**采集策略（关键是**不增加摩擦**）**：

| 手段 | 做法 |
|---|---|
| **只问 1 个** | 澄清阶段末问一句："你更希望我先给你**能跑的例子**，还是先讲清**原理**？" |
| **顺便抽取** | 在同一次画像抽取里**一起抽**（用户在对话中的表达方式已暴露偏好），不额外增加调用 |
| **行为推断** | 直接贴代码 → 偏动手；反复问"为什么" → 偏原理。**不增加任何提问** |

**e. 表现与进度**：当前方案（里程碑 + 执行窗口）、进度游标、**逐次验收的历史记录**、实际速度与估计的比值。

> **验收历史是当前完全缺失的一环**：现在只保留最近一次验收结论，**反馈没有"记忆"**，"认识你"只能靠画像做一半。

### 2.5.3 采集：谁写、什么时候写

| 维度 | 采集方式 | 写入时机 | 更新频率 |
|---|---|---|---|
| b 目标与用途 | **问** | 澄清阶段 | 目标变更时（**需确认**） |
| c 时间与节奏 | **问** | 澄清阶段 | 用户主动改 |
| d 学习偏好 | **问 1 个 + 抽取 + 推断** | 澄清起，持续 | 随对话修正 |
| a 起点水平（自评） | **问** | 澄清阶段 | 仅一次 |
| a 起点水平（判定） | **测 + 推断** | 测评阶段起 | **每次验收后** |
| e 表现与进度 | **推断** | 每次验收后 | **每轮** |

**必填（放行条件）**：要完成的任务、所属技能、单次可投入时长。
> 比早期版本**更聚焦**：**自评水平不再必填**——它降级为参考初值，真正的水平**由测评测出**。

### 2.5.4 一个已修的结构缺陷：画像被拼了三遍

早期版本里，同一份画像在三处被**各自手工拼装**，而且内容不一致：方案生成时用到了"薄弱点"，而**与教练对话时用不到**。

> **后果**：方案生成知道你的薄弱点，但**跟你对话的教练不知道**——个性化只做了一半。（缺陷编号 **X-18**）

**v0.16 的对策**：画像提供**唯一的渲染出口**，所有消费方共用。

**收益**：新增维度会**自动进入所有消费点**，不会再出现"某个地方漏了一项"。

### 2.5.5 数据流与敏感性

**数据流（全本机）**：用户输入 → 本机状态 → 组装提示词（阶段提示词 + **画像** + 参考 / 检索结果 + **本次学习摘要** + 最近若干条对话 + 本轮输入）→ **发送至第三方模型 API** → 回复与判定写回状态。

| 数据 | 敏感性 | 处理方与传输 | 保留 / 删除 |
|---|---|---|---|
| 用户输入 / 交付产出 | 中低（个人学习记录） | **传输至第三方模型 API**；本机留存 | 清空历史、完全重置、删除数据目录 |
| 用户画像 | 中低 | 随调用传输（**只注入必要内容**） | 同上 |
| 检索片段（启用后） | 公开内容；**视为数据而非指令** | 注入提示词 | 不落地为索引 |
| 模型输出 | 可能含错误 | 本机状态 | 覆盖写入 |
| 日志 / 评测样本 | 含学习记录 | **仅本机** | 不进入版本管理 |

**用户是否知道并可控制个性化**：部分——可见画像与薄弱点、可清空 / 重置（**含对话归档**）；**尚无个性化开关**（待建）。

**数据越界风险**：① 学习内容随调用传输第三方（**第三方数据条款待核**）；② 对话历史注入扩大暴露面与成本；③ 未来检索内容被误当指令。

### 2.5.6 记忆管理（**v0.18 设计**）

> 本节只写**产品口径**；实现细节见 [memory-design.md](memory-design.md)。

**问题**：只有"窗口化"是不够的 —— 它控住了**成本**，但没有解决**遗忘**。窗口之外的对话对系统**永久不可见**，而"记住我学到哪、薄弱在哪、下次直接接上"（UR-05）正是本产品的核心价值之一。

**分两层**：

| 层 | 装什么 | 用户视角 |
|---|---|---|
| **短期记忆** | 本次学习内发生的事（对话 + 本次学习的进行中摘要） | "它跟得上我这次在干什么" |
| **长期记忆** | 用户画像（五维度）+ 表现与证据 + 每次学习的记录 | "它记得我、认识我" |

**三条对用户的承诺**：

| 承诺 | 含义 |
|---|---|
| **关键事实不遗忘** | 判定与表现以**结构化记录**留存，**不依赖对话原文**；对话压缩只影响"怎么讲述"，不影响"事实" |
| **可解释** | 每一次掌握度变化都能追溯到**哪一次验收 / 测评**；"这个分数怎么来的"可以回答 |
| **可控制** | 可查看画像与薄弱点；可清空对话（**含归档**）与完全重置 |

**复习（标记待复验）**：长时间没有被任何任务覆盖的知识点会被**标记待复验**，在生成下一个计划块时**优先安排**。
触发条件：**连续 8 次单次学习未覆盖**该知识点。它不是独立阶段，而是排任务时的一条优先级规则。

**单次学习时长上限**：**120 分钟**。用户自报更长时长时，系统按 120 分钟安排并**明确告知**。

**与隐私的关系**：原文留存**仅用于审计**、不再注入模型；注入内容**只含必要信息**（画像 + 摘要 + 最近若干条原文）。详见 2.5.5 与 3.4（X-09 / X-11）。

**待实测调整的参数**（初值见 [memory-design.md](memory-design.md) §9）：注入预算、保留条数、evidence 明细条数。

## 2.6 生成式输出契约（模块 A）

| 项目 | 内容 |
|---|---|
| 输出类型与结构 | 对话为纯文本；**结构性输出一律走结构化（JSON）模式**，经校验与清洗后才允许进入状态（画像、测评题目、路线图与执行窗口、验收判定） |
| 内容边界 | 允许：教学解释、任务布置、判分反馈。需澄清 / 拒绝：超纲与不确定内容须声明；**敏感主题（心理 / 医疗）不得越界为专业诊断** |
| 来源或事实要求 | 本期**无自建知识库**，不强制逐句引用；**启用联网检索后**须定义"何种陈述需来源 + 如何展示引用" |
| 不确定性与缺信息 | 信息不足时只问 1~2 个关键问题；资料不足时先声明再补充并注明为通用知识 |
| 编辑与反馈 | 对话中可直接纠正；方案须确认后才执行；判定可被反驳并重做 |
| **可检验性（v0.16）** | **每个任务必须带可检验的完成标准**；缺失时该任务不合格（见 2.3 硬约束） |
| 提示词版本 | 提示词已集中管理；**版本化与回归仍未成体系，待补** |
| 专项评测 | 任务满足度、事实错误（幻觉抽样）、结构化输出可解析率、判分一致率（M-01） |

## 2.7 工具与编排（模块 C）

| 动作 / 工具 | 用途与输入输出 | 执行主体与权限 | 只读 / 可写 | 确认点 | 失败处理 |
|---|---|---|---|---|---|

## 2.8 评分与决策机制（模块 E）

| 项目 | 内容 |
|---|---|
| 预测目标与时间窗 | ① 逐题判定 掌握 / 部分 / 未掌握；② 逐次验收 完成 / 部分 / 未完成，并给出**证据是否充分**的判断；③ 聚合出知识点**掌握度**与**薄弱点排序**（阈值 <0.6）。窗口 = 当前执行窗口 |

| 数据与漂移 | 标签质量依赖模型判定；**无重训**；漂移源 = 模型版本 / 提示词变更 / 领域扩展 → 触发回归 |
| **验收强度的归口（v0.17）** | **验收强度由代码决定，模型不得自行放宽**——证据要求与"未完成不得通过"的一致性约束**由代码强制**。*（原"验收档位 L1/L2/L3"已移除，见 2.4）* |
| 解释与申诉 | 给出完成度 + 错误类型 + 理由 + 反馈；可反驳可重做；**正式申诉通道待建** |

# 第三幕 · 验收

## 3.1 成功指标与实验

| 类型 | 指标及操作定义 | 基线 / 获取 | 目标与时间窗 | 数据来源 |
|---|---|---|---|---|
| **首要结果** | **任务完成率** = 完成的任务数 ÷ 下发的任务数 | **待测**（自用） | **待定** | 采集 + 状态；**按领域分层** |
| 次要结果 | **首次验收通过率**；**薄弱点覆盖率**（后续任务命中此前薄弱点的比例）；**方案采纳率**（确认 ÷ 生成）；平均澄清轮数 | 同上 | 待定 | 同上 |
| **护栏** | 单轮 token 成本；P95 延迟；幻觉抽样率；**平均每轮模型调用次数** | 无基线，先测 | 不得高于基线 | 采集 |

> **注意**：完成率**上升不等于学习质量上升**——质量由**验收的证据要求与判分一致率**保证。只看完成率会奖励"把任务变小"。

**分析方法**：自用先建基线（**按任务统计**）；再小样本试用验证。**注意选择偏差与样本限制**（熟人、非随机、无对照）。
**判断时间点与决策**：待定。达标 → 扩展领域或加入 teaching 对比；未达标 → **先简化流程 / 收窄范围**。
**因果假设（待验证）**："完成率提升"代表"任务被有效推进"，**而非**"学习者已掌握"——后者需要**跨会话的证据累积**。

## 3.2 质量要求（五维）

| 维度 | 本项目指标 | 为什么重要 | 测量方法 | 目标 / 护栏 |
|---|---|---|---|---|
| **AI 任务质量** | 判分与人工一致率；方案可执行性（任务含可验收标准的比例）；事实正确性（幻觉抽样） | 判定错误会误导学习路径 | 评测集 + 人工复核 + 抽样 | 一致率 **≥90%（待定）**；关键链路 100% |
| **系统可靠性** | 守卫不误推进；端到端成功率；故障恢复 | 状态机跳级会破坏流程与信任 | 确定性测试 + 端到端矩阵 | 确定性测试 100% 通过；守卫硬断言 |

| **安全、隐私和公平性** | 数据去向（仅本机 + API 传输）；提示词注入；判定偏差 | 数据与公平是**红线**，不得标"不适用" | 数据流检查；注入用例；分层抽样 | 已列注入 / 越权用例 100% 阻断（**仅指已列用例**）；偏差待测 |
