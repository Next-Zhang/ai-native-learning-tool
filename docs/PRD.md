## 1. 产品摘要与阶段目标

为有明确能力目标、愿意持续练习的自学者提供 AI 学习教练：将目标拆为里程碑和任务，依据实际提交提供反馈，跨学习会话接续进度、补强与复验，帮助形成可独立应用的能力。

本阶段要证明三件事：学习闭环能够可靠执行；同一用户能够跨次接续；记录与调整能支持可观察的独立应用表现。
任务完成只证明本次产出符合要求，不能自动解释为能力掌握。

当前目标交付为单用户 Electron 桌面软件与本机数据，保留 CLI 作为开发验证入口；现有实现仍为 CLI。商业化、在线公开服务、多用户服务与自动提醒暂缓；不为个人原型虚构市场规模、营收目标或组织审批。

## 2. 用户、问题与证据

### 2.1 目标用户与首批验证对象

目标用户：已选定技能方向或能力目标，愿意提交练习产出并接受反馈，但难以安排下一步或判断进步的自学者。

🔶 假设 H-01：首批自用验证从 Python 数据分析开始，面向有基础计算机操作能力、Python 初学或基础不稳的成年人。
该范围用于降低首轮评测难度，不代表产品只支持编程，也不是已获用户研究验证的人群画像。
非编程领域在首条可靠闭环后验证；不据两领域通过宣称任意领域普适性。

首批场景中的用户愿意多次返回并主动提交。仅希望系统代做工作、没有练习意愿的使用不计为持续学习价值验证样本。

### 2.2 典型场景

| 场景 | 用户触发与输入 | 期待得到什么 |
|---|---|---|
| 首次建立目标 | “希望学会清洗 CSV 并分析销售数据，每次约 30 分钟” | 明确范围与达成标准，了解起点，确认近期安排 |
| 日常练习 | 继续当前目标，提交代码、解释或结果 | 获得任务验收依据，知道哪里要改 |
| 中断后返回 | 几天后或重启程序再次学习 | 看见未完成任务及接续点，不重新初始化 |
| 受挫与补强 | 任务部分完成、多次请求提示 | 调整练习或补前置知识，不反复照搬同一道题 |
| 复验与回顾 | 后续会话再次运用已练知识点 | 区分当时做对、独立应用与跨次保持 |

“30 分钟”等是示例，不作为用户容量下限或产品固定排期。

### 2.3 问题假设与替代方案

| 假设 | 待获得的证据 | 反例/调整方向 |
|---|---|---|
| H-02：用户难以确定下一步 | 过去真实学习中断或反复规划的经历 | 课程顺序已足够时，突出接续与反馈，减少规划负担 |
| H-03：用户需要产出反馈 | 实际做题时的错因、误判或求助行为 | 主要需求只是快速查询时，不强迫进入学习闭环 |
| H-04：跨次记录减少接续成本 | 返回后无需重复解释目标且能继续 | 记录未改变体验时，简化采集 |
| H-05：复验与调整支持独立应用 | 同类新任务及后续复验的有效表现 | 只提高原题完成率时，不能宣称形成能力 |

以上均为 🔶 假设，尚无正式用户访谈或对照证据。
替代方案包括课程、笔记与带历史/记忆的通用 AI；不能预设它们都无状态。
差异化假设是“可追溯的持续练习闭环具有增量”，验证方法与局限见验证报告。

## 3. 核心对象与流程

### 3.1 对象关系

学习目标 → 能力矩阵 → 测评与能力画像 → 路线图 → 里程碑 → 执行窗口 → 计划单元 → 任务。
目标级参考资料库为能力矩阵、测评与计划提供来源；计划版本关联采用的资料、能力差距和审核记录。
学习路径（Way）承载一个学习目标及其路线图、任务、进度、学习证据和对话记忆。当前只完成单路径；后续多路径范围见第 4.3 节，不能据此要求本期实现路径管理。
学习会话实际发生，可跨越或未完成计划单元；一个会话包含多轮对话。
任务/测评题目 → 提交 → 有效判定 → 学习证据 → 画像与后续安排；后续复验回到同一知识点。

每次任务验收、复验与纠错都必须可关联实际题目或任务、提交、结果及时间。
知识点的稳定身份不能仅依赖生成文本；任务改版不能使原提交自动适用于新要求。
这是产品数据语义，具体模型与持久化设计由架构负责。

### 3.2 用户流程

下表描述用户可进入的流程；第 3.3 节规定初始化与持续学习的整体顺序和放行条件，两者共同构成产品工作闭环。

| ID | 流程与进入条件 | 系统输出及结束条件 | 异常/分支 |
|---|---|---|---|
| FL-01 | 首次目标澄清：无可执行学习目标 | 明确能力、用途、范围、达成标准与单次时间预算；用户确认目标理解 | 模糊处每轮问 1～2 个关键问题；自评/期限缺失不阻塞 |
| FL-02 | 起点测评：目标清晰，首次或用户请求重测 | 呈现实际题目；有效作答建立初始证据，说明覆盖与未测范围 | 追问不计作答；系统失败可重试；用户不会计有效未完成，不与故障混淆 |
| FL-03 | 制定安排：有目标及起点信息 | 展示路线图、里程碑标准、近期任务与时间；用户确认后开始 | 不接受时收集修改理由；生成无效不得静默套用通用计划 |
| FL-04 | 学习与任务验收：已有确认安排 | 下发当前任务、支持练习、接收明确提交、解释有效判定并给出接续点 | 提问/提示请求不计提交；无效判定保留任务与提交 |
| FL-05 | 返回接续：存在历史状态或中断记录 | 展示目标、最近有效进展、未完成项；开始新的实际会话并确认当前可用时间 | 缺少可靠恢复点时说明，不推测用户已经完成 |
| FL-06 | 调整/暂停：用户改变容量、暂停或目标 | 保留进度；容量变更重排近期内容；实质变更说明影响并确认 | 拒绝/未确认保留原安排；系统失败不得擅自切换 |
| FL-07 | 后续复验：有待复验知识点且用户开始会话 | 安排关联知识点的新任务，计入时间预算，形成新证据 | 跳过保留待复验；提示/故障不形成独立保持结论 |
| FL-08 | 回顾与收尾：里程碑候选达成或用户主动结束 | 展示证据、未覆盖项与建议；区分达成结束和主动停止 | 证据不足可保留目标或停止，不写成已掌握 |

无有效题目、标准或提交时不能生成正式任务验收结论。
各流程描述产品行为，不与当前代码阶段一一等同；代码中的 completed 不可达等差距见交付清单。

### 3.3 Agent 完整工作闭环

项目负责人于 2026-10-14 确认：1.0 保留以下十个环节，先实现每个环节的最小可运行能力。步骤 1～6 为初始化，步骤 7～9 为持续学习，步骤 10 为周期回顾；回顾后的新计划重新经过审核、展示与确认，再进入学习。
本节描述目标产品行为，不代表现有 v0.18 代码已经具备这些环节。

| 步骤 | 输入与处理 | 必须保留的产物与放行条件 | 异常与用户干预 |
|---|---|---|---|
| 1. 目标与基本信息 | 根据用户陈述及少量提问，提取能力目标、用途、范围、学习节奏、单次时长及偏好 | 保存结构化信息及来源；目标理解和达成标准由用户确认；未知偏好可空 | 不编造偏好；用户可修正，自评或期限缺失不阻塞 |
| 2. 初始资料检索 | 围绕已确认目标进行真实检索，建立目标级参考资料库 | 保存资料标题、真实链接、来源类型、相关能力及用途、可访问性和检索时间；1.0 以官方文档为主 | 未获取正文的资料不声称读过；失效或不足说明并补检索，不编造资料 |
| 3. 能力矩阵与起点测评 | 结合目标和资料明确能力点、必要前置及可观察标准；用户确认矩阵范围后进行测评 | 保存能力矩阵、题目/作答/判定及初始画像；已测、未测和无法判断分开 | 自评不是能力证据；覆盖不足可形成显式不完整画像，不补成零分或声称测完 |
| 4. 补充检索与滚动计划 | 根据画像中的能力差距、偏好、节奏和预算补充检索，生成路线图及近期执行窗口 | 计划包含目标/能力点、安排理由、任务要求、时间和所用来源；来源与安排逐项关联 | 既有资料足够时可复用并说明；来源不支持内容、超预算或缺标准时修订，不靠贴链接充作依据 |
| 5. 计划自审核 | 主 Agent 对待审计划作显式审核，检查来源匹配、画像匹配及可执行性 | 留下对应计划版本的审核结论、问题与修改；通过后进入展示 | 未通过退回步骤 4；无法核实明确标记，不无限循环或以模型一句“通过”代替检查 |
| 6. 展示与用户确认 | 调用展示/导出工具生成用户可阅读版本，展示计划、来源、时间及审核结论 | 1.0 通过桌面界面展示可读计划及来源，可提供 Markdown 导出；CLI 用于基线验证；用户确认对应版本后初始化完成 | 拒绝则收集原因并修订、重新审核；输出失败或未确认不得开始正式学习 |
| 7. 任务执行与验收确认 | 从已确认计划生成单次任务，支持讲解、练习和反馈；对明确提交按原标准判定 | 呈现结果、依据、帮助程度及证据，用户确认验收后收尾本次学习 | 提问不算提交；用户可提出争议，暂停或退出保留恢复点；部分完成不强制写成全通过 |
| 8. 学习后更新 | 根据实际会话生成摘要，依据有效判定更新能力画像，依据明确表达或可追溯记录更新偏好 | 摘要、能力证据、偏好来源分开保存，记录更新成功/失败；再次处理不重复应用 | 摘要不生成能力结论；更新失败保留已保存记录并支持恢复，不伪报成功或覆盖用户新声明 |
| 9. 复习与复验调度 | 根据薄弱项、帮助程度、独立表现与保持证据安排复习/补强及复验 | 1.0 按 BR-07 执行最小调度：每会话自动至多一个复验任务，告知原因并计入预算 | 复习可包含讲解与练习；复习本身不等于独立复验，跳过不计失败 |
| 10. 7 天周期回顾 | 根据周期内任务、独立表现、复验、实际容量、偏好与争议回顾计划 | 输出保持原计划、调整计划或生成下一执行窗口的理由；有变更时回到步骤 4～6 | 周期内无学习或证据不足如实说明，不自动推断进步/遗忘；不因时间到达强制推进里程碑 |

### 3.4 Agent 职责与控制边界

项目负责人于 2026-10-14 确认采用“外层工作流约束 + 局部 ReAct”：外层保留十步闭环的必要依赖、用户确认与阶段放行；阶段内根据工具返回结果决定下一步。1.0 首先用于资料检索、计划生成与自审核修订；学习中追问/补强可复用该机制，具体扩展以验证结果为依据。
局部循环围绕一个明确子目标运行，从当前允许的能力中选择行动，执行并观察结果，再决定继续或退出。完成、等待用户、受阻或达到执行限制时退出；需要用户输入或确认时保存恢复点并暂停，不能在内部替用户作答或确认。代码再次校验前置条件、输入、授权和状态版本，模型提出行动不等于获准执行。
每次循环须有动作次数、总体时间和重复无进展的停止控制；具体数值在实现设计中确定并验证，当前不默认批准任何数值。它们与 BR-05 每逻辑调用含首次最多 5 次请求、120 秒的网络恢复限制分开计算。日志记录动作、简短选择理由、结果和停止原因，无需存储模型完整内部推理。
这一选择不要求引入新框架、独立 Planner/Executor 或独立 Review Agent。技术取舍见 [ADR-006](adr/0006-local-react.md)，代码现状仍以架构文档为准。

主 Agent 贯穿目标理解、检索、测评、计划、教学、判定、回顾和自审核；模型提出内容与结构化建议，系统检查合法性、有效性、版本及授权后保存和推进。
用户确认目标/能力矩阵、计划版本与任务验收；用户确认验收表示接受本次结果及收尾，不替代有效判定，不使有辅助、未知或未完成表现自动变成独立能力证据。用户未确认时保留待确认结果和有效提交，不按已验收任务推进；有效判定可保存供恢复与复核，不能重复应用。

自审核是生成计划后的独立步骤，审核对象为指定版本的计划、来源和画像。至少逐项检查：资料是否实际支持对应安排；难度/前置/补强是否符合画像及未测边界；任务与标准是否明确、总时间是否可执行。自审核通过不等于独立第三方审查或质量保证。
后续加入 Review Agent 时沿用上述审核输入、输出和退回规则，由独立角色承接审核职责；主 Agent 继续生成与修订计划。职责可分离，但仍须验证上下文交接、来源核验、审核可靠性和失败恢复，不能据角色拆分直接宣称质量提升。

学习后“后台更新”指用户完成本次学习后由系统处理的收尾工作；1.0 可在当前进程执行，不要求常驻服务或独立任务队列。进程退出后不承诺继续运行，待处理更新须可恢复；异步实现不能让旧结果覆盖新记录。
7 天为计划回顾周期，与第 8.3 节的自用观察跨度分别记录。1.0 可在用户返回时检查周期是否已到并执行待处理回顾，不要求无人值守定时运行或主动通知；周期起点与已处理范围须记录，避免重复调整。周期边界的具体时间计算在实现设计中明确，不以计划单元计数代替经过时间。

### 4.3 后续目标：多个 Way 保留、单个激活

项目负责人于 2026-10-14 确定：后续支持保留多个学习路径，每次只激活一个；当前先完成单路径。
每个目标对应一个 Way，分别保留路线图、任务、进度、提交、学习证据与对话记忆。创建新目标时可新增 Way；切换只改变当前激活路径，不清空其他路径，返回原路径可接续原待办。
教学、任务提交、判定和自动复验均归属当前激活 Way；不默认混用其他路径的聊天、任务或掌握结论。跨路径证据复用与共享偏好策略在该功能启动时另定。
多路径管理、存储重组及切换验收属于后续版本，不作为本期验收或 PRD 定稿阻塞。本期无需预建空路径、多路径接口或通用调度框架。

## 5. 持续学习业务规则

### BR-01：目标与放行

目标必须包含能力、用途/场景、范围和可观察达成标准；本次时间预算明确。
系统可帮助拟定，但须向用户确认理解；自评、每周次数、截止日期及偏好可空。
自评只影响测评起点，不成为掌握证据。无法形成可检验目标时保持澄清并说明原因。

### BR-02：时间预算与任务有效性

每个任务必须先有练习要求、交付物和验收标准；预先说明允许的参考资料和工具。
单次时间预算涵盖讲解、练习和反馈。计划单元内三类活动的预计总时长不得超过预算；下发时展示总量及大致分配，不能将讲解或反馈默认作为额外占时。
按任务复杂度、已有表现和本次讲解需要动态估计，不设置固定分配比例；需要增加讲解或反馈时相应缩减练习量。预计时长是规划依据，不承诺实际完成时间精确可控。
预算不足时应缩小任务或协商，不增加预算，也不能只把预计分钟数改小而保留全部工作。
不设统一最低时长。保留用户实际可投入的时间，按容量安排有效练习、答疑或复验；无法形成有效内容时说明原因并协商，不自动提高预算。此项已由项目负责人于 2026-10-13 确认。
用户改变预算后，已开始任务的原要求和原提交保留；可建议拆分，实质修改任务须确认并区分版本。

临近预算且仍有未完成内容时提示用户，由用户选择继续或暂停；不自动延长预算，也不因预算耗尽判任务失败。
O-01 已于 2026-10-13 确定：不设统一最低时长；讲解、练习和反馈全部计入，动态分配，不固定比例。具体估计实现由技术方案落实。

### BR-03：提交与任务验收

只对用户明确提交给当前任务/题目的内容进行正式判断；提问、请求提示、闲聊、空输入不消耗作答机会。
判定须绑定用户实际看到的题目/任务及其版本，不能用新生成问题或教练自述替代。
有效结果分完成、部分完成、未完成，并列出对应标准、依据和下一步。
有效判定先向用户展示；用户确认验收后才按该结果推进一次。未确认或有争议时保留结果、原提交和恢复点；用户确认不改变判定的完成度或独立性。重复处理同一提交不重复写证据或推进。
证据不足时说明缺少什么；无法判断不映射为未完成。

### BR-04：帮助程度与能力结论

帮助程度记录为独立、参考允许资料、有影响作答的提示/答案、未知；显示来自交互记录或用户声明。
任务事先允许查 API 文档等资料时，遵守该约定不自动算有辅助；影响作答的提示必须保留。
系统无法观察外部辅助，不承诺验证真实性；未知不计为独立应用证据。

任务结果与能力证据分开展示：分别呈现任务完成度、帮助程度、独立应用证据与跨次保持证据，不用总体掌握分数或百分比概括能力。此展示方式已由项目负责人于 2026-10-13 确认。
“待复验”作为单独标记，不是能力等级，也不因需要复验而自动降低已有证据状态。证据不足时显示“尚无有效证据”或“尚未复验”，不能显示为零分。
同一道题反复重做通过，不作为未见过的同类任务；有辅助完成不直接升级为独立证据。
一次合格表现即可展示“已有独立应用证据”：任务对应明确知识点和约定难度，是未做过的同类任务，满足预先定义的验收标准，且没有影响作答的提示或答案；可使用任务事先允许的资料。帮助程度须有交互记录或用户声明，未知不计为独立。
展示对应任务、时间、证据数量及帮助来源；同一有效结果只计一次。一次证据不代表能力掌握或跨次保持。此项已由项目负责人于 2026-10-13 确认。
“已有跨次保持证据”须关联一条原独立应用证据，在后续实际学习会话完成同一知识点的另一项新任务，仍满足独立完成条件，并且间隔至少 16 小时。一次有效复验即可记录；16 小时是本版产品操作阈值，不代表已经证明长期保持。此项已由项目负责人于 2026-10-13 确认。
间隔按原独立应用任务的有效提交时间至复验任务首次呈现时间计算；记录两条任务/证据及实际间隔。时间记录不足时不能推定达到阈值；不足 16 小时的有效复验可保留复验记录，但不标为跨次保持证据。
“能力掌握”必须限定目标范围、证据来源与时间，不由完成度直接换算。

O-02 已于 2026-10-13 确定：结果与证据分开展示；一次合格独立表现即可展示；后续会话至少间隔 16 小时独立复验一次可记保持；里程碑推进不等待复验；达成标准以综合任务覆盖必需项，详见 BR-10。

### BR-05：无效判定与恢复

API 不可用、超时、缺必需字段、题目/提交错配、证据不足均不得写成能力零分、消耗有效测评题或推进任务。
保留最后成功保存的进度和本次有效提交，显示原因类别及重试/稍后继续入口。
保存失败时不得显示“已保存”；说明最后可靠恢复点。进度已写与回复失败需区分，不重复应用结果。
生成失败不得伪装成合格方案；通用草稿须标“尚未验证可执行”，不能自动进入学习。
请求失败须区分四类：调用前缺凭据/配置错误、请求期间临时故障、返回内容无效，以及有效判定为未完成。后者不是系统故障；无效输出按 AI 能力契约处理，不能与网络重试混用。
同一次逻辑模型调用（目的及输入不变）仅针对临时网络故障、临时限流或服务端异常自动重试；包含首次调用，总共最多 5 次请求，即最多 4 次自动重试。底层客户端与业务层统一计数，不能分别重试导致超过总上限。此次数规则已由项目负责人于 2026-10-14 确认。
每次逻辑模型调用从首次请求发起开始，总等待上限为 120 秒，包含全部请求执行时间及重试间隔；次数或时间上限先到即停止，不必试满 5 次。120 秒约束单个逻辑调用；整轮可能包含多个逻辑调用，不能将其视为整轮耗时上限或正常响应的 P95 目标。此等待规则已由项目负责人于 2026-10-14 确认。
逐步延长重试间隔，遵守服务端有效等待指示；等待指示超过剩余预算时停止本次逻辑调用。向用户展示重试进展并允许取消；达到上限后提供主动重试或稍后继续入口，不后台无限运行，保留任务和提交。
缺凭据/配置错误不自动重试；空内容、缺字段或任务错配不进入此临时故障重试循环。请求超时不保证服务端未处理，须保留逻辑调用与提交身份，避免重复应用判定、写证据或推进。
取消、超时终止或已被重试取代的请求，其迟到结果不再作为有效输出应用，不更新任务、进度、学习证据或对话记忆；结果返回时须检查调用是否仍有效。用户主动重试使用新的调用标识，关联原任务与提交；旧调用不能覆盖新结果。此项已由项目负责人于 2026-10-14 确认。
终止前已成功保存的有效结果保留，不因取消回滚；仅回复未完成时如实告知已保存部分，恢复时不重复应用。原任务、提交与可靠恢复点保留，取消不计为用户作答失败。可记录请求状态及迟到结果被忽略的事件，不将迟到内容当作学习事实。不能承诺取消能撤销服务端计算或费用。
当前原型暂不设置按金额自动停止的规则，不因累计费用达到某一值而自动中断学习。记录可获得的输入/输出 token、请求及重试次数、已知单价下的估算费用；单价或用量不明时标记未知，不按零费用展示。继续遵守每逻辑调用最多 5 次请求、总等待最多 120 秒及用户取消规则。此成本策略已由项目负责人于 2026-10-14 确认；扩大试用或计费模式改变时再评估预算机制。
整轮正常响应时间先测基线，当前不设硬性性能验收门槛；记录端到端 P50/P95、失败等待及各类操作的耗时，等待时展示进展并允许取消。正常成功轮次与含故障/重试的轮次分别报告，不能把后者隐藏或用单次调用耗时替代整轮。此策略已由项目负责人于 2026-10-14 确认；后续根据真实使用与实测数据另行修订性能目标，不将本期未设硬门槛解释为无需观测。

### BR-06：学习会话与接续

用户实际开始学习时创建会话；主动结束、暂停、进程退出或异常中断时保留最后可靠恢复点。
不按无交互时长自动结束或切分学习会话。用户可能在练习，沉默、跨自然日或跨计划单元均不能单独视为结束；预算耗尽先提示，由用户选择继续或暂停。
主动结束、暂停、退出或使学习交互无法继续的异常中断时结束当前会话，返回学习时创建新会话并接续原任务。单次模型调用失败或超时不自动结束会话，按 BR-05 保留进度并允许恢复。
重启后先呈现接续摘要，不因重启重新测评；原提交待验收时优先处理，不用返回问候覆盖提交。
会话、计划单元、自然日、对话轮分别记录。不能因游标跨单元就推断用户发生了跨次回访。
同一会话中改变时间预算不必创建新目标。O-03 已由项目负责人于 2026-10-14 确定：不因无交互自动结束，以明确操作或实际交互中断为边界。

### BR-07：补强与最小复验

有效未完成/部分完成进入补强候选，反馈对应缺失标准；可以拆分任务、补前置练习或换解释，必须说明原因。
不允许无限重复原题或仅降低验收标准。关键前置能力不足时先补强，再安排更难任务。

RP-01 已确定：每个实际学习会话检查复验候选，自动安排至多一个复验任务，并在安排时明确告知用户所涉知识点、复验原因、预计用时及占用的本次预算；用户可跳过，跳过不判失败且保留待复验。没有合格候选或预算无法适配时不强行安排。此项已由项目负责人于 2026-10-14 确认。
自动安排不得覆盖已有任务或待验收提交，按 FL-05 接续原待办；一个会话内已下发的自动复验即计入数量上限，跳过后不再自动补发另一项。用户主动要求更多复验不受自动数量上限限制，但仍受实际时间预算约束。
保持复验须满足 BR-04 的至少 16 小时间隔；补强确认的有效表现可保留为复验记录，未满足保持条件时不称跨次保持。
候选按以下顺序选择：（1）补强后待确认的知识点；（2）已有独立应用证据、尚无保持证据且满足至少 16 小时间隔的知识点；（3）已有保持证据且适合再次复验的知识点。同类候选按距上次有效表现的时间由长到短排序；不能将系统故障当作补强候选的依据。该顺序已由项目负责人于 2026-10-14 确认。
一个复验任务可以覆盖多个相关知识点；“至多一个”限制任务数，不限制知识点数。优先选主知识点，再按任务相关性和预算合并其他合格候选，不为凑知识点扩大范围或超预算。安排时列出所覆盖知识点及各自原因，验收时分别关联标准、结果、帮助程度与证据；每个知识点独立检查 16 小时间隔和保持条件。
综合任务部分完成时，只有达到对应标准的知识点可记录有效完成证据；其他项保留未完成/无法判断及补强需要，不能因一项做对而将全部知识点标为通过或保持。各项结果来自同一提交，但保持独立关联，重复处理不得重复留证。

复验结果须关联同一知识点和新任务；有效独立完成形成复验记录，达到 BR-04 的后续会话及至少 16 小时间隔要求才可补充跨次保持证据，失败进入补强候选，
有辅助或无法判断保留边界。用户跳过不计失败且保留待复验；旧证据不删除。
本版不另设将知识点判为“已遗忘”的时间阈值；“最久未练习”用于合格候选排序，不自动降低既有能力证据，也不是要求所有知识点到期强制复验。

### BR-08：调整与确认

首次路线图、目标范围改变、任务/里程碑标准改变、已确认方案实质重建、数据删除和人工纠正判定均须明确确认。
确认必须展示操作及影响，并绑定具体版本；拒绝、取消、异常或未明确同意均不执行。
改变目标后保留旧目标的有效记录，不把旧授权用于新目标。
只调整表达、在既有目标和容量内安排等价任务可自动执行并说明；一旦扩大范围、增加预算或改变达成标准，重新确认。
窗口滚动不是无条件授权下一批内容；按以上实质变化规则判断。

### BR-09：质疑与纠错

用户质疑时显示原标准与依据，允许补充信息、重新作答或请求复核；不要求用户先接受原结论。
争议原记录保留并标记待复核；争议项不作为新增掌握结论或跳过教学的依据。
有效纠正新增关联记录并更新派生判断；说明谁/什么过程纠正。故障重试不记为用户重做失败。
人工“标记掌握”属于人工纠正来源，不能伪装成测评通过。

### BR-10：里程碑回顾与结束

里程碑开始前有阶段达成标准；任务列表排完只触发回顾，不直接标记能力达到。
达成量规以综合任务为主，适用于里程碑与最终学习目标：系统按能力范围拟定“目标产出、必需标准、允许资料/工具、独立完成要求”，在开始前供用户确认；具体内容随领域和目标生成，不硬编码成全领域统一题单。
用一个或少量未做过的综合任务覆盖全部已确认必需标准；逐项关联有效独立表现证据，一项任务可以覆盖多个知识点。缺哪项就针对该项补验，不要求每个知识点都另做一道题，也不以其他项高分抵消必需项缺失。有争议或无效证据不能算对应项已覆盖。
回顾展示标准覆盖、帮助程度、独立与跨次证据、待复验及争议项；满足已定义标准才可标达成。
满足阶段达成标准并具备对应独立应用证据后，可推进下一里程碑，不必等待至少间隔 16 小时的复验。应用达成与跨次保持分别展示，未复验不会自动阻塞推进。此项已由项目负责人于 2026-10-13 确认。
后续复验发现关键前置能力不足时安排补强，并据影响调整后续任务；保留历史有效证据，不把一次失败静默改写为过去从未达成。实质改变目标/阶段标准或重建安排仍按 BR-08 确认。
全部必需标准均有对应有效独立证据时，可标记阶段/目标应用达成并展示依据；保持证据仍单列，不据此宣布长期或全面掌握。具体量规在每个目标/里程碑开始前确认，实质变更按 BR-08 重新确认。综合任务为主的方式已由项目负责人于 2026-10-13 确认。
用户可随时主动停止，标记“主动停止”并保留进度；不强制完成全部任务后才允许结束。
建立新目标须明确确认，不静默继承旧目标的完成标志。

### BR-11：记忆与数据控制

画像区分用户声明、有效表现与派生结论；偏好可修改、不阻塞学习。摘要只用于接续，不写能力判定。
用户可查看有效记录及重要记忆来源，并纠正错误。
自动采集、压缩、回取与有界保留属于记忆管理；主动清理仅处理用户明确的忘记/重置请求，不是学习或切换目标的默认步骤。后续新增/切换 Way 不依赖清空旧目标，当前单路径的清理行为与多路径未来设计分别处理。
“清除对话记忆”删除原文、归档与叙事摘要，使其不再注入；结构化学习证据若保留必须先说明。
“重置学习进度”回到新目标起点；“删除全部本机个人数据”另含备份与诊断内容，不能互相替代。
若本版不提供彻底删除入口，必须说明手动范围并避免声称已彻底删除。第三方已接收内容不承诺由本机删除。
本期保留证据与叙事分工、有界保留和实测后调参方向；记忆管理按第 5.1 节四模块目标设计演进，现有参数仅作实现起点，不代替类型规则和缺陷修复。通过真实使用核对接续质量与来源可追溯性，再调整参数，不新增按自然日自动清空学习状态的规则。早期明细可能被裁剪或降采样，不能承诺全部原文和证据明细永久保存。此项已由项目负责人于 2026-10-14 确认。
本期保留现有清对话/重置操作，修复摘要残留和非原子写等不一致，不新增三个清理入口；清对话保留结构化学习状态，完全重置需说明备份/日志仍保留。彻底删除本机个人数据提供明确手动范围说明，不伪装为既有重置已经完成。用户未主动操作时按记忆管理规则保留，不因新目标设想自动清除。
沿用策略不恢复已被产品决策替代的旧业务规则：复验候选按 BR-07，实际会话按 BR-06；现有代码以计划序号和 8 次未覆盖触发的旧规则仍需后续调整，不能据 O-06 当作新复验的额外门槛。
供应商数据留存、训练用途等属于外部待核事实，扩大试用前核实并告知；不由产品偏好决定，也不阻塞本机原型 PRD 的需求定稿。

### 5.1 记忆与数据控制要求

产品层统一称“产品数据管理与访问层”，按领域管理数据；Agent 的主动存取和上下文预加载都通过相应 Router 检查主体、Way、用途、字段及写入资格。默认拒绝未定义访问，模型不可读取系统凭据、完整权限策略或独立验收标签；不可自行修改业务确认、进度或有效证据。见 [数据权限与 Router 设计](data-access-design.md)。

2026-11-01：以下行为要求继续有效，但旧“四模块管理全部产品数据”的所有权范围由 ADR-008 修订。业务状态/证据、资料、运行检查点各有所有者；上下文组装跨服务读取，狭义记忆保留 Router、记忆存储和生命周期职责。AC-30～35 按所有者联合验收，不授权记忆直接管理业务状态或工具执行。

当前学习目标对应的学习路径（Way）是主要记忆作用域，跨多个实际会话保留。1.0 只做单 Way，明确目标与记录归属，不提前实现多路径管理；未来多 Way 保留、单个激活的范围不变。
记忆管理分为 Router、存储、上下文组装与注入、生命周期管理。Router 按类型与来源确定写入资格；存储维护记录/版本/引用和一致性；上下文按任务及预算读取；生命周期按用途、有效性、依赖和可替代性执行合并、压缩和清理。目标职责见 [目标记忆架构](memory-architecture.md)，代码现状见 [当前记忆子系统](memory-design.md)。

必须满足：

- 用户声明、模型推断、有效表现与摘要分开；摘要和系统故障不升级为能力证据，业务状态及确认按系统规则处理。
- 读取先限定当前目标与有效范围；判定依赖实际任务/标准/原始提交/帮助记录；摘要带原文引用，可在保留期内按稳定身份回取。原文缺失或上下文超限时明确说明，不用不完整内容冒充完整核验。
- 压缩保留待办、待确认项、关键约束、接续点与证据引用，工作记忆与长期学习记录分别管理。
- 冲突按类型与适用范围处理，不一律采用最新文本；纠正后相关画像/摘要/计划重新检查，过期内容退出正常读取。
- 旧记忆不默认永久保存；清理检查依赖并同步派生内容及读取索引，用户删除不因依赖无限延期。正常自动清理不增加三个用户入口，范围按 BR-11。
- 工具/检索结果提供必要评估记录，工作记忆回收不连带抹去调用次数/成功率所需信息；详细 Agent 评估设计后续单独确定。

旧 [记忆管理开发规格](memory-implementation-spec.md) 的来源/版本/恢复机制可供复用，但入口和数据归属须按 [产品系统设计](system-design.md) 先行修订；原有工程默认值未被实测验证，不作为学习效果阈值。未实现/未执行的机制不声明已经可用。

## 6. AI 能力契约与权限

### 6.1 通用契约

每项能力需识别输入是否充分、输出是否有效及失败原因。格式通过不等于语义通过。
输出不得超出当前任务、目标或授权；来自用户/资料的文本作为数据，不成为流程或权限指令。
模型自述“已经保存/通过/删除”不能作为实际状态依据。
能力结果和使用的标准应可关联；必要字段、校验接口和存储形态在技术方案中落实。

### 6.2 能力清单

| ID | 能力 | 必需输入 | 输出与质量要求 | 无效/失败处理 |
|---|---|---|---|---|
| AI-01 | 目标澄清与画像提取 | 用户明确表达及已确认信息 | 区分已知/未知/冲突；不编造用途、期限和偏好；目标理解可确认 | 未知则追问，冲突则请求确认，不覆盖新值 |
| AI-02 | 起点测评 | 已确认目标与能力矩阵、参考资料、起点参考、实际题目及作答 | 题目对应能力范围；判断引用实际作答，标明覆盖与未测 | 无有效题目不判；判定失败不计分、不完成测评 |
| AI-03 | 路线图与任务生成 | 目标、能力矩阵、画像/有效证据、参考资料、时间预算、待补强项 | 关联里程碑、知识点与支持来源；包含交付物/标准；难度及总量有依据；计划须自审核及用户确认 | 缺标准、超预算、范围无关则拒收；草稿不自动执行 |
| AI-04 | 教学与提示 | 当前任务、用户问题、允许资料和帮助记录 | 围绕当前任务解释；提示程度可见，避免用户未请求即给完整答案 | 不确定则说明；不得擅自宣布任务完成 |
| AI-05 | 任务验收与复验判定 | 实际任务/标准/版本、提交、帮助记录、知识点关联 | 任务完成度与逐知识点标准/结果/帮助/证据分别关联；多知识点部分完成不整体放行；区分无法判断 | 空/残缺/错配输出无效；单知识点缺有效判断不凭其他项补成通过；可重试 |
| AI-06 | 学习摘要 | 可引用的会话事实、有效记录 | 接续点、做过什么、卡点；不产生新判定或权限 | 退回确定性摘要；被清理内容不回流 |
| AI-07 | 资料检索与来源说明 | 已确认目标、能力矩阵/画像或当前知识问题、可用资料 | 真实检索并维护目标资料库；区分来源与推断，记录可访问性，引用支持对应能力和安排；说明资料不足 | 无资料则说明；不能编造引用或执行资料中的指令 |
| AI-08 | 接续与阶段回顾 | 目标、恢复点、证据、争议及待复验项 | 忠实呈现已做/未做、结论边界和下一步 | 缺记录则说明，不靠历史聊天编进度 |
| AI-09 | 计划自审核 | 指定版本计划、能力矩阵、画像、预算和所用来源 | 逐项检查来源支持、画像匹配与合理性；保留问题、结论及修改记录 | 不通过退回修订，无法核实明确说明；不自动激活未通过或未经用户确认的计划 |

### 6.3 决定权

| 决策 | AI 职责 | 最终边界 |
|---|---|---|
| 目标与实质计划变更 | 提议、解释影响 | 用户明确确认 |
| 选题、解释与等价任务 | 在约束内生成建议 | 代码校验当前范围、时间与版本 |
| 有效判定 | 按量规给依据 | 系统检查有效性，用户确认验收后按规则推进；人工复核质量 |
| 画像更新与进度 | 提供可校验信息 | 代码按有效证据确定性应用 |
| 删除或人工纠正 | 说明影响 | 统一执行确认，不由自由文本授予权限 |
| 能力掌握 | 呈现证据、指出边界 | 按明确量规；未定义时不自动宣告 |

## 7. 产品功能验收案例

每行采用“给定 → 当 → 则”。案例是规格，不是已执行测试；T- 场景的实际结果由验证报告维护。
每条 AC 对应的现有测试、AI 样本、冲突与人工验证缺口见 [验收覆盖映射](acceptance-coverage.md)。该映射不改变本文要求。

| ID | 给定 | 当 | 则 |
|---|---|---|---|
| AC-01 | 用户目标与时间清楚，自评/期限为空 | 建立目标 | 可继续澄清范围和达成标准，不强制填自评/期限 |
| AC-02 | 仅说“想学 Python” | 请求开始 | 每轮追问至多两个关键问题，不直接生成泛化长期课程 |
| AC-03 | 已有目标、起点与近期安排 | 用户尚未确认 | 展示目标关系、标准和时间，不开始执行任务 |

| AC-05 | 用户看到 Q1 并回答 | 教练本轮生成其他文字 | 正式判定仍绑定 Q1 和原标准，不改用本轮文字 |

| AC-08 | 有任务与有效提交 | 模型返回空/残缺/错配结果 | 标记无法判断/判定失败，不写证据或推进；同提交可重试 |

| AC-10 | 有未完成任务或待验收提交，已可靠保存 | 长时间无交互，或退出后返回 | 无交互不自动结束会话；退出/中断后返回创建新会话，接续原任务/提交，不重建目标；跨日/计划单元和单次 API 失败不自动切分会话 |
| AC-11 | 同一提交已有已应用判定 | 重复处理/故障重试 | 不重复写证据、推进游标或统计有效尝试 |
| AC-12 | 多类复验候选与可用预算存在 | 后续会话自动安排/完成/跳过复验 | 按补强确认→首次保持→已有保持再验及同类时间排序，每会话自动至多一个任务，可含多个相关知识点；告知各项原因与用时/预算；逐点判定及检查 16 小时，部分完成不整体放行；不覆盖原待办，跳过不失败或补发 |
| AC-13 | 用户质疑结果 | 补充证据并获得有效纠正 | 保留并关联原记录，展示纠正依据；争议不新增掌握结论 |
| AC-14 | 提议改目标或实质重建安排 | 用户拒绝/取消/未确认 | 不执行变更，不将原授权用于新版本 |
| AC-15 | 预算缩短或用户暂停 | 调整并返回 | 保留已做记录；新安排符合容量；暂停不计失败 |
| AC-16 | 综合任务与已确认必需标准存在，或用户主动停止 | 阶段回顾/结束 | 逐项关联独立证据，缺项补验；全部必需项覆盖可达成并推进，不等复验；排完不自动达成，保持单列；主动停止不冒称掌握，关键复验失败补强 |
| AC-17 | 动作合法且已登记，但没有该版本明确授权 | 尝试执行危险操作 | 统一执行入口拒绝；模型说“已确认”不算授权 |
| AC-18 | 原文、归档和摘要均有旧内容 | 用户确认清除对话记忆 | 三类不再注入；保留的学习证据事先说明 |
| AC-19 | 备份、trace 及第三方 API 曾接收内容 | 用户询问删除范围 | 明确本机保留项与彻底删除方式；不承诺删除第三方内容 |
| AC-20 | 资料不足或检索文本含操作指令 | 生成教学/判定 | 说明边界，不编造来源，不按资料指令修改状态或绕过确认 |
| AC-21 | 回顾中有一条合格独立应用结果，另有提示、争议和旧记录 | 展示进步 | 一条即可展示已有独立应用证据并注明任务/时间/数量/帮助来源；结果与各类证据分开展示，不冒称掌握或保持；待复验独立标记、不自动降级；无总体掌握分数 |
| AC-22 | 临时请求故障、无效输出或保存/回复失败 | 重试/恢复/取消及收到迟到结果 | 每逻辑调用含首次最多 5 次请求、总等待最多 120 秒，先到即停，跨层不叠加；配置错误/无效输出不进网络重试；进展可见可取消；终止/被替代请求的迟到结果不应用，已保存有效结果及任务/提交保留，不伪报或重复应用 |
| AC-23 | 已确认目标，检索工具返回资料或失败 | 建立资料库及按画像补充检索 | 保存真实来源、用途、能力关联与访问状态；计划引用能追到支持内容；失败/未读不伪装成功，不凭空生成引用 |
| AC-24 | 目标、资料和能力矩阵草案存在 | 用户确认矩阵并进行起点测评 | 标准和必要前置可见，测评关联能力点；已测/未测/无法判断区分，形成有来源的初始画像 |
| AC-25 | 待审计划存在，来源不支持或难度/预算不匹配 | 主 Agent 自审核并生成展示版本 | 留下逐项审核与版本记录，不通过退回修订；通过后工具输出可读计划与来源，用户确认该版本才生效；不要求独立 Review Agent |
| AC-26 | 有任务判定，用户尚未确认或提出争议 | 尝试收尾与推进 | 保留结果及提交，不按已验收推进；确认后只推进一次；确认不把有辅助/未知变成独立证据，不覆盖原争议记录 |
| AC-27 | 单次学习已收尾，摘要/能力/偏好更新成功或失败 | 学习后更新及中断恢复 | 三类记录有依据且分开；摘要不创造能力结论，偏好不编造；失败可见，保留已保存结果，恢复不重复应用或覆盖新记录 |
| AC-28 | 7 天周期已到，存在学习证据或缺少有效表现 | 用户返回触发周期回顾 | 根据真实记录说明保持/调整/生成计划的理由，证据不足不推断进步或遗忘；新/改计划经自审核与确认；不重复处理，不要求后台通知 |
| AC-29 | 局部循环有子目标、允许能力与配置的执行限制 | 选择工具、收到新结果或遇到确认/异常/限制 | 只执行经系统校验的合法行动；依据结果继续或退出，等待用户时暂停保存；重复无进展与达到限制时停止；不绕过审核/确认或直接改证据；记录行动与停止原因，循环限额与网络重试分开 |
| AC-30 | 混合消息、摘要、有效判定或失败事件产生候选 | Router 筛选存储 | 按类型/来源/当前 Way 校验；可拆多条，未知或缺依据不升级；摘要不写能力证据，模型不能授予确认；业务状态按原规则执行 |
| AC-31 | 当前任务需要原文，存在稳定引用或已清理记录 | 查询并组装上下文 | 先限定当前 Way/有效范围，按消息/任务/会话取回原文及必要上下文；缺失或超限明确说明，不据残缺内容正式判定 |
| AC-32 | L1 待处理内容含接续点、待确认项及长文本 | 压缩、归档并生成 L2 | 必需接续信息与证据引用移交后才退出当前记录；未处理部分不静默视作已压缩；ReAct 工作记录与长期记忆分开 |
| AC-33 | 同范围新声明、争议证据或迟到更新存在 | 保存与读取派生内容 | 按类型处理替代和争议，保留必要来源；一致版本更新，旧结果不覆盖新记录，相关画像/摘要/计划更新或标记过期 |
| AC-34 | 冗余、过期或用户要求删除的记忆仍有引用 | 生命周期清理 | 按用途/有效性/依赖清理并同步派生内容及索引；正常清理不留悬空依据，用户删除不因依赖无限延期，删除内容不被旧运行结果复活 |
| AC-35 | 工具或检索失败后子任务结束 | 清理临时工作记忆 | 回收临时内容，保留必要结果与未解决项；评估所需执行事件不连带丢失，失败不成为学习能力不足证据；具体统计协议另定 |

本版 O-01～O-09 已确定；局部 ReAct 架构选择见第 3.4 节，循环参数另由实现设计明确；测试应依据已定规则。后续调整须记录规格版本与理由，不能将候选参数或未执行案例写成验收通过。
独立讲解巩固模式不在本版，不能以教学对话通过冒充 UR-12 已验收。

## 8. 成功标准与试用门槛

### 8.1 指标定义

首要结果指标是独立应用表现；接续、复验和完成率用于解释机制与执行，不能替代学习效果。

| M-09 | 去重后完成任务数 / 去重后已下发任务数 | 撤销/跳过另列；任务改版留关联，防靠变小或重复计数提高指标 |

学习收益、留存与成本基线尚不足，不补造数字。
评测样本、运行配置、实测值与局限在验证报告；已确定的目标和门槛维护在本节及第 10 节决策汇总。

### 8.2 试用门槛

- 已列核心确定性案例全部通过；与行为相关的 P1 缺陷关闭并复验；无效判断不污染能力记录。
- 真实模型覆盖首次、任务验收、跨次接续、复验与故障；实际执行和错误完整报告。
- 人工复核量规与评测标签，judge/domain/risk 等关键分层不被均值掩盖。
- M-01 初始一致率至少 90%；人工先按标准独立判定再比较 AI，争议样本保留处置依据，不把人工意见默认视为绝对正确。关键错误必过样例不能以总体一致率抵消；无有效比对样本或覆盖不足时不能声明达标。
- 独立验收集至少 30 条不同样本，覆盖起点测评判定、任务验收、提交识别、计划确认、画像提取这 5 类，每类至少 6 条，覆盖正常、边界和对抗情形。样本与标签经人工复核，验收前冻结，不用于日常提示词/规则调优；据失败样本反复调整后需补充新的未用于调优样本。数量要求已由项目负责人于 2026-10-14 确认。
- 重复运行不增加独立样本数，近似复制不能代替行为覆盖；至少 30 条是本版起点，不是统计充分性或学习效果的证明。该数据集评价模型判定点，不能替代 AC 流程、跨次接续或人工体验验证；当前数据数量与执行情况只在验证报告登记。
- 冻结数据集、代码、模型配置和量规，对同一套独立验收样本完整评测 3 次，每次分别报告总体与 judge/domain/risk 分层，一致率每次均须 ≥90%，关键错误必过案例每次全部通过；不以 3 次均值、多数投票或择优轮次代替。重复要求已由项目负责人于 2026-10-14 确认。
- 30 条运行 3 次为至少 90 次样本评测，不增加独立样本数；自动网络重试属于单次逻辑调用恢复，不算额外一轮评测。故障/无效结果完整记录，有效覆盖不足时该次不能声明达标，不通过只重跑失败条目来覆盖原完整运行结果。配置或规则改变后重新执行完整协议并记录变更。
- 明确数据处理边界、删除语义、授权与可取消行为。
- O-04 的请求次数、120 秒上限、取消及迟到结果隔离等行为经过验证；按已确定策略记录费用和性能基线，不另造金额/正常延迟硬门槛。
- O-06 的本机保留/重置范围已明确，扩大试用前核实供应商数据处理事实；O-07 的判定评测及持续学习观察按第 8.1～8.3 节执行，不由报告自行降低要求。
- 扩大试用前完成第 8.3 节自用观察，报告未完成、失败与效果边界；不设置学习提升百分比硬门槛。

上述是要求，不是通过声明。公开发布、商业化与多用户另行评审。

### 8.3 持续学习观察协议

O-07 已由项目负责人于 2026-10-14 确定：先由项目作者围绕同一个学习目标，完成至少 5 次实际学习会话，观察跨度至少 7 天。
会话按 BR-06 的实际开始、结束和中断记录计数，不能用计划单元、跨日或人为重启凑次数；观察跨度从首次实际学习开始到最后一次观察，至少经过 7 天。
至少包含一次中断后返回，以及一次在后续会话独立完成的复验；复验按 BR-04 从原有效提交至新任务首次呈现至少间隔 16 小时，并关联同一知识点及两次证据。

开始前确认目标范围、量规和起点任务；后续使用未见过的可比任务，记录独立表现、帮助来源、错误及改正、接续情况和复验结果。按 M-06～M-09 配对与分层报告，保留故障、跳过、有辅助、未知和争议记录。
先获得学习表现基线，不设置必须提升多少百分比的门槛；没有改善也是有效观察结果，不据此改量规或隐藏失败。未完成规定会话、观察跨度或有效独立复验时，协议仍为未完成，如实说明原因。
这是单人自用的机制与体验观察，不证明普遍学习收益、长期保持或相对于其他方案的因果增量。后续外部用户研究的样本规模和比较设计另定。
本协议尚未执行；记录格式和实际产物由验证报告维护，不将历史 API 会话累计数充作本协议结果。

## 9. 体验、可靠性与依赖

| 主题 | 需求与限制 |
|---|---|
| 可理解性 | 用户可看见目标、当前任务、任务标准、有效结果与下一步；错误提示不直接暴露原始异常或凭据 |
| 反馈与等待 | 说明当前进行的操作；可以退出/稍后继续，退出不等于撤销已应用结果；保存情况如实反馈 |
| 连续性与恢复 | 进度以可靠保存点为准；幂等应用结果；错误不伪装成用户失败 |
| 隐私 | 只传完成当前能力所需内容；说明模型 API 去向、备份和诊断数据；供应商条款扩大试用前核实 |
| 质量边界 | AI 判定并非客观执行证明；编程未接执行环境时明确未运行代码，不声称运行成功 |
| 内容范围 | 首批按 H-01 验证；医学、法律等高影响用途另审，不直接套用首批量规 |
| 模型依赖 | 单一模型 API 可能波动；模型/提示词/量规改变须复核关键案例，不以低温保证稳定 |
| 运行环境 | 单用户本机 Electron 桌面 + Python 后端，保留 CLI 验证；无并发编辑、多用户隔离或服务 SLA 承诺 |
| 知识来源 | 目标级真实资料检索与计划来源关联属于核心；本地 RAG、视频解析和代码执行器的技术选型按实现需求决定 |

主要风险：用户实际只想代做、评分不可靠、帮助程度不可观察、记录误关联、流程摩擦与长期观察不足。
风险缓解分别通过样本筛选、有效判定/人工复核、帮助来源标注、稳定对象关联、观察首个任务成本与跨次验证处理。
缓解存在不表示风险消除；实现缺口与运行事件分别进交付清单和验证报告。
